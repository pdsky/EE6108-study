TOPIC 1

计算机网络导论

Session 1–2

Topic 1 回答三个问题：网络由什么组成（节点、链路、协议，以及边缘/接入/核心和 LAN/WAN 两种分类）；数据在网络里怎么走、要花多久（电路交换和分组交换、四类时延、存储转发）；怎么把这么复杂的系统组织起来（分层协议、封装、TCP/IP 和 OSI 模型）。最后介绍衡量网络好坏的指标：时延、丢包、吞吐量。期末常考的是存储转发时延公式的推导和统计复用的概率计算。

1.1 网络是什么

讲义的定义（slide 10）：计算机网络是网络节点（node）、网络链路（link）和网络协议（protocol）的集合。网络只提供一种基本服务：传输信息。不同网络的区别在于传得多快（带宽 bandwidth）、等多久（时延 latency）、丢多少（丢包率 loss rate）、能接多少端系统，以及可靠性、单播还是组播、是否实时等。

网络的组成部件（slide 11–12）

通信介质可以是电压/电流、无线电或光。协议最容易被忽略：链路接好了，如果双方对消息格式、先后顺序、收到后做什么没有共同约定，照样无法通信。讲义 slide 42 用打招呼类比：人说 "Hi" 对方回 "Hi"，再问 "Got time?"；电脑先发 TCP connection request，对方回 response，再发 "Get EE6108_Lecture1.pdf"，对方回文件。

1.2 分类一：边缘 · 接入 · 核心

网络结构的三部分（slide 13–17）
  • 网络边缘 Network edge：端系统（主机），运行应用程序。两种工作模式：Client/Server（客户端请求、服务器提供服务，如浏览器和 Web 服务器、邮件客户端和服务器）；Peer-to-peer（很少或不用专用服务器，主机之间对称，每台既是客户端又是服务器，如 BitTorrent）。
  • 网络核心 Network core：路由器互联成的网状网（network of networks）。数据在核心里有两种传法：电路交换和分组交换（下一节）。
  • 接入网 Access network：把端系统连到第一台路由器（edge router）的那一段，也就是"最后一公里"的通信链路。

1.3 分类二：WAN / LAN，以及电路交换 vs 分组交换

为什么分组交换能服务更多用户（slide 27–28）

例题：一条 1 Mbps 链路；每个用户活跃时要 100 kbps，只有 10% 的时间活跃。

  • 电路交换：每人都要预留 100 kbps，最多 1 Mbps ÷ 100 kbps = 10 个用户。
  • 分组交换：放 35 个用户进来。只有同时活跃的人超过 10 个时链路才不够用。每人独立地以 p = 0.1 活跃，活跃人数服从二项分布：
P(恰好 n 人活跃) = C(35, n) · 0.1n · 0.935−n P(活跃人数 > 10) = 1 − Σn=010 C(35, n) · 0.1n · 0.935−n ≈ 0.0004 "贪心"放 100 人：P(> 10 人活跃) ≈ 0.417 （slide 28，这时拥塞就很频繁了）

结论：大多数时间里，分组交换网络能服务的用户数远多于它的容量"按预留算"能容纳的人数。这叫统计复用，前提是用户流量有突发性，大家不会同时说话。

  • 题目没说就默认：排队时延 = 0，没提处理时延就忽略；传播速度取 2×108 m/s。
  • 本课 k = 103，M = 106（不是 1024）；字节 ×8 变比特。m（毫）和 M（兆）写混是考试常见失分。

分组从 A 经过路由器到 B，在每一跳都要经历四种时延（slide 29–32）。把一个分组想成一队车过收费站：

时延发生了什么公式取决于
处理 nodal processing检查比特错误，决定从哪条出链路发出去通常给定或忽略路由器速度
排队 queueing处理完进队列；只有前面没有分组、出链路空闲时才能发Q / R到达时队列里已有的比特数 Q

传输时延 ≠ 传播时延

传输时延只看分组多长、链路多快，跟距离无关；传播时延只看距离多远，跟分组大小无关。slide 31 的两个对比：

  • P = 1 KB（8000 bit），R = 1 Gbps，100 km 光纤：P/R = 8 µs，T = 105/(2×108) = 500 µs。传播时延远大于传输时延（T ≫ P/R）。
  • P = 1 KB，R = 100 Mbps，100 m 铜缆：P/R = 80 µs，T = 0.5 µs。传输时延远大于传播时延（T ≪ P/R）。

排队时延（slide 32）：分组到达时队列里已有 Q bit，它要等这 Q bit 全部发完才轮到自己，所以等 Q/R。一个分组从开始发送到完全到达下一跳的总时间 = 排队 Q/R + 传输 P/R + 传播 T。

1.5 存储转发与报文分段

老师强调 · 课堂录音
  • 不要背公式，画时序图：每条链路一行，有传播时延时方块画成斜的。
  • 常见错误：拓扑读错（几跳）；每段链路上分组编号标错；每个分组都要加首部（如 80 字节）后再算传输时延；处理时延是每个分组在每个节点都有。
  • Rs = Rc 与 Rs > Rc 吞吐量一样，但速率不匹配会在缓存处丢包；缓存不是越大越好（时延变大）。

存储转发（store-and-forward）：交换机必须先把整个分组完整收下，才能往出链路发它的第一个比特（slide 33）。所以一个大分组过每一跳都要付一次完整的传输时延。把长报文切成小分组后（slide 34），第一个小分组很快传到下一跳，下一跳开始往前发它的同时，上一跳已经在发第二个分组，各段链路同时在工作，像流水线。

公式推导（slide 35）

报文 m bit，切成 N 个分组，每个分组载荷 k = m/N bit、首部 h bit，经过 L 跳（L 条链路、L−1 台交换机），每条链路速率 R。忽略传播和排队，交换机可以同时收和发。

一个分组的传输时间 T = (k + h) / R 不分段（整个报文当一个分组）：Tm = L · (kN + h) / R 分成 N 个分组：D = L·T + (N − 1)·T （第一个分组走完 L 跳；后面 N−1 个分组每隔 T 到一个） TN = (L + N − 1)(k + h) / R

1.6 分层协议体系与封装

网络有主机、路由器、各种介质的链路、应用、协议、软硬件，非常复杂。讲义用航空旅行类比（slide 44）：买票 → 托运 → 登机口 → 跑道起飞 → 航线 → 跑道降落 → 登机口 → 提取行李 → 投诉，每一层只和对面同一层打交道，并依赖下一层提供的服务。

  • 一个系统使用的协议列表，每层一个，叫协议栈 protocol stack。
  • 分层的目的：把网络设计、实现和维护的复杂度降到可以管理的程度；一层的改变不需要改其他层。
  • 层数和每层功能没有自然规律规定。第 N 层建立在第 N−1 层提供的服务之上，并向第 N+1 层提供服务。

1.8 流量类型与网络指标

弹性与非弹性流量（slide 58）
弹性流量 Elastic非弹性流量 Inelastic
能适应 Internet 上时延和吞吐量的变化。传统"数据"类 TCP/IP 流量。不容易适应时延和吞吐量的变化。"实时"流量，例如语音和视频。

应用对网络的三类要求（slide 59）：数据丢失（音频能容忍一些丢失；文件传输、telnet 要 100% 可靠）、时延（网络电话、互动游戏要低时延）、带宽（多媒体要最低带宽；"弹性应用"有多少用多少）。

丢包和时延是怎么产生的（slide 60–62）

分组在路由器缓存里排队：到达速率超过出链路容量时，分组排队等待（时延）；没有空闲缓存时，新到的分组被丢弃（丢包）。丢失的分组可能由上一个节点、源端系统重传，或者根本不重传。

R = 链路带宽（bps），L = 分组长度（bit），a = 平均分组到达速率（个/秒） 流量强度 traffic intensity = La / R La/R ≈ 0：平均排队时延很小；La/R → 1：平均排队时延很大；La/R > 1：到达的比特比能发出去的多，排队时延趋于无穷

吞吐量与瓶颈链路（slide 63）

吞吐量 throughput：发送方和接收方之间传送比特的速率（bit/时间）。瞬时吞吐量是某一时刻的速率，平均吞吐量是一段较长时间的速率。服务器经速率 Rs 的链路、再经速率 Rc 的链路到客户端：端到端吞吐量 = min(Rs, Rc)。限制端到端吞吐量的那条链路叫瓶颈链路。

2 Mbps ÷ 200 kbps = 10 人。前提是流量有突发性：每个人只有一小部分时间在发，同时活跃超过 10 人的概率很小。如果每个人一直在发，分组交换就没有优势。
1500 字节分组，10 Mbps 链路，长 2 km（s = 2×10⁸ m/s）。传输时延和传播时延分别多少？
传输 = 1500×8 / 10⁷ = 1.2 ms；传播 = 2000 / (2×10⁸) = 10 µs。传输时延大 120 倍。
报文切成 N 个分组过 L 跳，为什么总时间是 (L+N−1)T，而不是 L·N·T？
第一个分组要一跳一跳走完 L 条链路，用 L·T。在它往前走的同时，后面的分组紧跟着在前面几段链路上传，所以第 2 到第 N 个分组只是每隔 T 到达一个，再加 (N−1)·T。各段链路同时工作，所以不是串行的 L·N·T。
交换机和路由器在封装上分别处理到哪一层？哪一个分隔广播域？
交换机处理到链路层（看 MAC 地址），路由器处理到网络层（看 IP 地址）。路由器分隔广播域，广播帧不会被路由器转发。
流量强度 La/R = 0.95 说明什么？
链路几乎被占满：平均到达比特速率是链路容量的 95%。按 slide 61 的曲线，这时平均排队时延非常大；一旦超过 1，队列无限增长，最终丢包。

TOPIC 2.1

数据链路控制：流量控制与差错控制

Session 2–4 · 必考

链路层负责把一个数据报从一个节点送到物理上相邻的下一个节点。这一章讲它的两件核心工作：流量控制（发送方别把接收方淹没：停等、滑动窗口）和差错控制（= 差错检测 + 重传 ARQ）。计算题集中在三处：链路效率 U（含误码时的三种 ARQ），Checksum，CRC。往年每卷都有 Checksum/CRC，大多数卷有 ARQ 效率。

2.1 链路层做什么

老师强调 · 课堂录音
  • 物理层不考；纠错（error correction）不考，只考检错。
  • 术语（slide 3）：主机和路由器都叫节点；沿通信路径连接相邻节点的信道叫链路（有线、无线、LAN）。链路层信道有两类：广播（LAN、无线 LAN）和点到点（如 HDLC）。第 2 层的 PDU 叫帧 frame，它封装数据报。
  • 同一个数据报一路上可能经过不同链路协议：第一段以太网，中间帧中继，最后一段 802.11。每种链路协议提供的服务不同（slide 4）。

IEEE 802 把链路层分成两个子层（slide 8）：LLC（向上提供接口，做流量和差错控制）和 MAC（发送时组帧，接收时拆帧、识别地址、检测差错；在广播链路上用多址协议管理对共享信道的访问）。链路层在"适配器"（网卡 NIC）里实现，是硬件、软件、固件的组合（slide 9）。

2.2 停等流量控制

老师强调 · 课堂录音
  • 简化模型 U = 1/(1+2a) 只有在题目满足假设（无开销、无处理、ACK 很短）时才能用；否则用一般模型：减掉首部开销、加上处理时间与 ACK 传输时间。
  • 效率 efficiency = 利用率 utilization，同一个东西。

接收方为发来的数据预留一块缓存。如果发送方发得比接收方处理得快，缓存就会溢出。流量控制让接收方告诉发送方什么时候可以继续发（slide 11–12）。讨论流量控制时假设所有帧都正确到达，没有丢失和错误。

停等 Stop-and-Wait（slide 13）：发一帧，等对方的 ACK，收到 ACK 才发下一帧。接收方可以故意晚发 ACK 来让发送方暂停。大块数据分成很多小帧发送时，停等效率很低。

发送方tframe等待 2tprop（ACK 时间忽略）
tframe = L/R（帧长 L bit，速率 R bps）　tprop = d/V（链路长 d，传播速度 V） 发一帧的总时间 TD = 2tprop + tframe （忽略 ACK 传输、处理、排队和开销） a = tprop / tframe = (d/V)/(L/R) = Rd / (VL) U = tframe / TD = 1 / (1 + 2a)　　有效传输速率 Reff = U · R = L / TD

a 的直观含义：以发一帧的时间为单位，信号在链路上要走多久。a < 1（帧很长或链路很短）时 U 接近 1；a ≫ 1（卫星、长光纤、高速率）时停等几乎都在等。

中间的"管道"就是链路。帧是一个有长度的色块：它的长度对应 tframe（发完一帧要多久），管道的长度对应 tprop（一个比特走完链路要多久），所以管道长 ÷ 帧长 = a。拖动 a，看 a < 1 时帧比链路还长、a 很大时发送方几乎一直在等 ACK。最下面的条是发送方的忙闲记录。

2.3 滑动窗口

老师强调 · 课堂录音
  • 第一步永远先判断：W ≥ 2a+1（满载）还是 W < 2a+1（欠载），两种情况算法完全不同；满载直接写 U = 1，不用算。
  • 注意题目给的是往返还是单程传播：Example 3 的 540 ms 已经是 2tprop。老师算法：tframe = 16 000×8 / 2 Mbps = 64 ms，2a = 8.44，2a+1 = 9.44。
  • RR 是累积确认：RR3 表示 0–2 都收到了，期待帧 3。

停等的问题是一次只能有一帧在路上。滑动窗口（slide 20–22）允许多帧同时在途：

  • 接收方有能放 W 帧的缓存；发送方不等 ACK 最多可以连发 W 帧。
  • 每帧编号，序号字段 k 位，帧号按 模 2k 循环。3 位序号 → 帧号 0–7，窗口 W = 7（最多连发 7 帧）。
  • 累计确认：ACK 带的是"下一个期望的帧号"。RR i 表示第 i−1 帧及之前都收到了，接下来期待第 i 帧。
  • 接收方可以发 RNR（Receive Not Ready）确认帧但暂不允许继续发；之后必须发正常确认才恢复。
  • 发送方窗口随发帧收缩，随收到 ACK 扩张（扩张量 = 本次 ACK 号 − 上次 ACK 号）。
取 tframe = 1，tprop = a。第一帧的 ACK 在 t = 1 + 2a 时回到发送方。 Case 1：W ≥ 2a + 1 → ACK 在窗口用完前回来，发送方一直在发：U = 1 Case 2：W < 2a + 1 → 窗口在 t = W 时用完，等到 2a+1：U = W / (2a + 1) 滑动窗口效率最多是停等（1/(1+2a)）的 W 倍

Example 3（slide 27）：无差错 2 Mbps 卫星信道，16 KB 数据帧，反向 ACK 很短，往返传播 540 ms。窗口 1、7、15、128 时最大吞吐量？

tframe = 16 000 × 8 / (2×106) = 64 ms；2tprop = 540 ms（往返已给）2a = 540/64 = 8.44 → 2a + 1 = 9.44W = 1：U = 1/9.44 = 0.106 → 212 kbpsW = 7：U = 7/9.44 = 0.742 → 1.483 MbpsW = 15、128：W ≥ 9.44 → 满载，不用算 → 2 Mbps老师课上按 16 KB = 16 000 字节（k = 10³）。若按 16 384 字节：216 kbps、1.515 Mbps。

2.4 差错控制：三种 ARQ

老师强调 · 课堂录音
  • 超时时间默认 = 一个往返时间。
  • 基础题里 ACK 默认无差错；复杂题里“成功”= 数据帧和 ACK 都无差错。
  • GBN / SR 的性能分析是比本科新增的内容，重点准备。

帧在传输中会出两类错（slide 30）：丢失帧（噪声突发把帧毁到认不出）和损坏帧（帧能认出但有比特错）。差错控制的手段组合：差错检测、肯定确认 ACK、超时重传、否定确认 NAK 加重传。ARQ（自动重传请求）把不可靠的链路变成可靠的：保证分组按序、无错、无重复地交付。

Go-back-N 的三种出错情形（slide 35）

  • 帧损坏：A 发帧 i，B 发现错误丢弃。若 A 接着发了 i+1，B 收到乱序帧，回 NAK(i)，A 重发 i 及之后所有帧；若 A 暂时没再发，B 什么都不回，A 超时后重发 i。
  • ACK 损坏：B 收到 i 回 ACK(i+1) 但丢了。因为 ACK 是累计的，A 可能收到后面某帧的 ACK，一并确认。若 A 先超时，就重发 i 及之后所有帧。
  • NAK 损坏：A 最终会在该帧上超时，重发该帧及之后所有帧。

2.5 有误码时的 ARQ 效率

定义 U = tframe / ttotal，ttotal 是为成功发出一帧所花的全部时间（slide 38）。p 是一帧出错的概率，假设 ACK/NAK 从不出错。Nr 是成功发一帧平均要发多少次（slide 39–40）：

Pr[恰好 i 次] = pi−1(1 − p)　→　Nr = Σ i·pi−1(1 − p) = 1/(1 − p) 停等 ARQ：U = 1 / [Nr(1 + 2a)] = (1 − p)/(1 + 2a)

Go-back-N（slide 41–42）：每次出错要重发 K 帧。原帧要发 i 次时总共发了 f(i) = 1 + (i−1)K 帧，Nr = (1 − p + Kp)/(1 − p)。最坏情况：W ≥ 2a+1 时 K = 2a+1，W < 2a+1 时 K = W。选择重传（slide 43）只重发出错那一帧，Nr = 1/(1 − p)。

三种 ARQ 的效率公式（考试直接用）
W ≥ 2a + 1W < 2a + 1
停等 ARQ（W = 1）U = (1 − p) / (1 + 2a)
Go-back-NU = (1 − p) / (1 + 2ap)U = W(1 − p) / [(2a + 1)(1 − p + Wp)]
选择重传 SRU = 1 − pU = W(1 − p) / (2a + 1)
往年题都要先从 BER 算 p（slides 没写这一步）

题目给的是误比特率 BER，每个比特独立出错。一帧有 n 个比特，全部正确的概率是 (1 − BER)n，所以帧错误率：

p = 1 − (1 − BER)n　≈ n · BER（n·BER 很小时）

例：1200 字节帧（9600 bit），BER = 5×10−5 → p = 1 − (1 − 5×10−5)9600 = 0.381。注意 n 用整个帧（含首部）的比特数，不只是载荷。

"载荷吞吐量"要再乘一次载荷比例

往年题常说帧 480 字节 = 400 字节数据 + 80 字节开销，问 "average data payload throughput"。这时 载荷吞吐量 = U × R × (载荷/帧长)。如果题目给了 ACK 帧长度，可以把 ACK 传输时间计入一个发送周期：周期 = tf + 2tprop + tack，相当于把 2a+1 换成 周期/tf。讲义公式忽略 ACK，两种做法的差别一般在 1% 左右，写清楚自己的假设即可。

slide 44 的曲线（P = 10−3）：a 很小时三种都接近 1；a 增大时停等最先掉下来；W = 7 的 GBN 和 SR 几乎重合，在 a ≈ 3 后下降；W = 127 时 SR 比 GBN 撑得更久，a 接近 100 才明显下降。

2.6 差错类型与奇偶校验

  • 独立比特错误（随机比特错误信道）：随机选中的比特翻转，彼此独立；主要由白噪声造成。
  • 突发错误（长度 B）：连续 B 个比特，第一位和最后一位错，中间任意位错；由脉冲噪声或无线信道衰落造成，数据速率越高影响越大。

差错检测的思路（slide 48–49）：发送方给 k 位信息加 n−k 位校验位，组成 n 位码字；接收方用收到的码字重新计算。目标是校验位尽量少、能检测的错误模式尽量多。

单比特奇偶校验（slide 50–53）

  • 加 1 位，使码字里 1 的个数为偶数（偶校验）或奇数（奇校验）。偶校验位 = 所有信息位模 2 相加。例：1100110 → 偶校验位 0 → 1100110 0。
  • 能检测所有奇数个比特错误；偶数个错误全部漏检（例如两位错 1101010 0 仍是偶数个 1）。只能检测 50% 的错误模式。开销 1/(k+1)。
  • 漏检概率 = 出现偶数个错误的概率：C(n,2)p²(1−p)n−2 + C(n,4)p⁴(1−p)n−4 + …。n = 32，p = 10−3 时讲义近似为 496×10−6 + 35960×10−12 ≈ 4.96×10−4，约每 2000 个错误漏 1 个（保留 (1−p) 因子精确值是 4.81×10−4）。

二维奇偶校验（slide 54–55）

把信息排成矩阵，每行末尾加行校验位，最后加一行列校验位。任意 1、2、3 个错误都能检测；4 个及以上的错误不一定（四个错误正好落在矩形四个角上时，每行每列都偶数个变化，检测不到）。早期差错控制系统用过。缺点是校验位太多。

往年考法：分块的一维偶校验（2024/25 S2 Q2(a)(i)）

12 位数据 1101 1101 0001，块长 6 位：110111 有 5 个 1 → 校验位 1；010001 有 2 个 1 → 校验位 0。发送的码字：1101111 0100010。

老师强调 · 课堂录音

模 2 多项式运算（slide 63–66）

  • 比特串对应多项式：10101101 → x⁷ + x⁵ + x³ + x² + 1（最高位对应最高次）。
  • 加法和减法都是按位异或，没有进位和借位：(x⁷+x⁶+1) + (x⁶+x⁵) = x⁷ + x⁵ + 1（因为 1+1 = 0）。
  • 乘法：(x+1)(x²+x+1) = x³ + x² + x + x² + x + 1 = x³ + 1。
  • 除法像十进制长除法，但每一步做异或。余数的次数一定低于除数。

发送和接收（slide 62, 67–71）

  1. 信息 M(x)（n+1 位），选一个 k 次生成多项式 C(x)（k+1 位）。
  2. 在 M 后面补 k 个 0，即 M(x)·xk，除以 C(x)，得到余数 R(x)（k 位，不足补前导 0）。
  3. 发送 T(x) = M(x)·xk − R(x) = M(x)·xk + R(x)，就是原数据后面接上 k 位余数（称为 FCS）。T(x) 能被 C(x) 整除。
  4. 接收方把收到的 T′(x) 除以同一个 C(x)：余数为 0 → 认为无错（或有检测不到的错）；余数非 0 → 有错。

补充 slide：x 的幂次除以 g(x) 的余数有周期（Session 4）

Checksum vs CRC 怎么比较（往年 3 次考过）

Checksum：只累加值、不看顺序；运算简单，适合软件实现，所以用在每跳都要重算的 IP 首部；字调换、插入删除全 0 字、互相抵消的错误都检测不到。CRC：多项式除法同时考虑值和位置；用移位寄存器硬件实现；按四条性质，选好的 C(x) 能检测所有单比特、奇数个、双比特错误和长度 ≤ k 的突发错误，检错能力强得多，所以链路层（以太网 CCITT-32）用 CRC。

2.2-1 共享信道与三种思路

两类链路（slide 3）：点到点（一条专用链路连一对收发方）和广播/共享（多个站共用一条或几条链路，如有线以太网、802.11 WiFi、卫星，就像鸡尾酒会上大家共用空气说话）。关键问题是怎么共享介质：同一时刻只能有一个站使用介质，需要 MAC 协议仲裁。

三种共享思路（slide 4）

2.2-3 ALOHA 与时隙 ALOHA

老师强调 · 课堂录音
  • a 很大（卫星）时时隙 ALOHA 反而比 CSMA 好。

ALOHA（slide 15）源自夏威夷大学主校区和分校之间的无线链路，没有中央仲裁。规则最简单：有数据就发；两帧同时在信道上就互相干扰（碰撞）而丢失；超时没收到 ACK 就随机退避一段时间再重发。

  • F：帧传输时间（定长）；S：吞吐量，每 F 秒平均成功传输的帧数；G：负载，每 F 秒平均尝试次数（含重传）。S = G · Psuccess。
  • 脆弱期 vulnerable period：一帧在 t0 开始发送，只要在 [t0 − F, t0 + F] 内有别的帧开始发送就会碰撞。ALOHA 的脆弱期 = 2F。
  • 假设到达服从泊松分布，2F 内 k 次到达的概率 = (2G)ke−2G/k!，没有其他到达的概率 = e−2G。
纯 ALOHA：S = G · e−2G　dS/dG = 0 → G = 1/2 → Smax = 1/(2e) ≈ 0.184 时隙 ALOHA：S = G · e−G　G = 1 时 Smax = 1/e ≈ 0.368

时隙 ALOHA（slide 19–20）：时间分成长度 = F 的时隙，各站同步到时隙边界，只能在时隙开始时发送，退避也按时隙整数倍。只有前一个 F 内到达的帧才会碰撞，脆弱期缩短到 F，最大吞吐量翻倍。

ALOHA 的双稳态行为：G 小时 S ≈ G；G 很大时 S → 0，碰撞会滚雪球把吞吐量拖到零。

讲义练习（Session 4 补充 slides 7–8）

若干终端通过 2400 bps 的公共信道和主机通信，每个终端平均每 2 分钟发一条 200 bit 消息。最多能接多少终端？

每个终端的平均速率 = 200 bit / 120 s = 1.667 bps 纯 ALOHA：S = 2400 × 0.184 = 441.6 bps → 441.6 / 1.667 = 265 个 时隙 ALOHA：S = 2400 × 0.368 = 883.2 bps → 883.2 / 1.667 = 530 个

2.2-4 CSMA：先听再说

老师强调 · 课堂录音
  • CSMA 的易损期 = tprop；CSMA/CD 的时隙 = 2tprop，不要混。
  • 纯 CSMA 工业上不用；CSMA/CD 用的是 1-persistent。

载波侦听多址 CSMA（slide 22）：发送前先侦听信道。忙就等或退避，闲就发。A 在 t = 0 开始发，信号 tprop 后传遍信道，之后别人都能听到 A 在发，所以脆弱期缩短到 tprop。但一旦碰撞，整帧时间都浪费掉。帧足够长（tprop/F ≪ 1）时效率高；若 tprop > F（a > 1），相比 ALOHA 没有好处。

策略行为时延效率

2.2-5 CSMA/CD 与以太网

老师强调 · 课堂录音
  • CSMA/CD 效率推导不考，记住 1/(1+6.44a) 会用就行。
  • 时隙 = 512 bit 时间：10 Mbps 下 51.2 µs，100 Mbps 下 5.12 µs。
  • 10Base5 = 10 Mbps、基带、500 m。

CSMA/CD（slide 25）：边说边听。先侦听，开始发送后继续监听介质；检测到碰撞，所有涉及的站停止发送，各自随机退避后重试。CSMA 碰撞会浪费整帧时间，CSMA/CD 只浪费检测到碰撞并中止的时间。

最坏情况要 2tprop 才能检测到碰撞（slide 26）：A 在 t = 0 开始发，B 在 A 的信号到达前一刻（t = tprop−）也开始发；B 在 tprop 检测到碰撞，B 的信号要再走 tprop 回到 A，A 在 2tprop− 才检测到。

效率推导（slide 27–29）

  • CSMA/CD 有三种状态：竞争、传输、空闲。竞争期按 2tprop 分成时隙，n 个忙站每个时隙各以概率 p 发送。
  • 恰好 1 个站发送时竞争成功：Psuccess = np(1−p)n−1，在 p = 1/n 时最大，(1 − 1/n)n−1 → 1/e。平均要 e = 2.718 个时隙，平均竞争期 = 2e·tprop。
  • 成功后用 F 发帧，再过 tprop 下一个竞争期开始。
ρmax = F / (F + tprop + 2e·tprop) = 1 / [1 + (2e + 1)a] = 1 / (1 + 6.44a) a = tprop/F = (d/V)/(L/R) = Rd/(VL)

四种协议怎么比较（slide 31；2025/26 S1 Q2(b)、S2 Q1(a) 都考过）
  • a 小（帧长、链路短、速率低）时 CSMA/CD 吞吐量最好，其次非坚持 CSMA、1-坚持 CSMA。
  • CSMA 一族的吞吐量都随 a 增大而下降：侦听到的是 tprop 之前的状态，a 越大信息越过时。
  • ALOHA（0.184）和时隙 ALOHA（0.368）不依赖 a，曲线是水平线。所以 a 较大（a 接近 1）时，ALOHA 和时隙 ALOHA 反而更好。
  • 时延角度：1-坚持时延低效率低；非坚持效率高时延高；CSMA/CD 检测到碰撞就停，浪费最少；时隙 ALOHA 要等时隙边界，比纯 ALOHA 多一点时延但效率翻倍。

以太网（slide 32–37）

  • 第一个以太网标准用 CSMA/CD：1-坚持侦听，R = 10 Mbps，时隙 512 比特时间（10 Mbps 时 1 比特 = 0.1 µs，所以 51.2 µs），截断二进制指数退避。
  • 无连接（网卡之间不握手）、不可靠（接收网卡不回 ACK/NAK，丢的数据报靠上层 TCP 恢复）。
  • 拓扑演变：90 年代中期之前流行总线（同轴电缆，所有节点在同一个碰撞域）；现在星形为主，中心是有源交换机。
  1. 网卡从网络层收到数据报，组帧。
  2. 侦听到信道空闲就开始发；信道忙就等到空闲再发。
  3. 整帧发完没检测到别的发送，这一帧就完成了。
  4. 发送中检测到别的发送：中止，发 32 bit 的 jam 信号，确保所有发送方都知道碰撞了。
  5. 进入截断二进制指数退避：第 m 次碰撞后，从 {0, 1, …, 2m − 1} 中随机选 K，等 K × 512 比特时间，回到第 2 步。10 次碰撞后上限固定在 1023 个时隙；16 次碰撞后放弃并报告失败。

以太网比 ALOHA 好得多，低效主要来自碰撞（slide 37）。发大帧更有效（抢到介质后一次发很多）。节点越多（要更多碰撞才能选出唯一发送者）、帧越小（仲裁更频繁）、链路越长（碰撞要更久才能发现），效率越低。

2.2-6 无线局域网与 CSMA/CA

  • 无线网络的组成（slide 39）：无线主机（笔记本、IP 电话，可以移动也可以不动）、基站（通常连有线网，负责转发，如 802.11 接入点 AP）、无线链路（多址协议协调访问，速率和距离各不相同）。
  • 基础设施模式：基站把无线主机接入有线网；主机换基站叫切换 handoff。Ad hoc 模式：没有基站，节点只能和覆盖范围内的节点通信，自组织成网并互相路由。
  • 无线链路更难（slide 40）：信号强度随距离衰减（路径损耗）；其他设备的干扰（2.4 GHz 和电话等共用）；多径传播（信号经反射，到达时间略有不同）。给定调制方式，加大功率 → SNR 升高 → BER 降低；给定 SNR，选满足 BER 要求且吞吐量最高的物理层（BPSK 1 Mbps、QAM16 4 Mbps、QAM256 8 Mbps）。

隐藏节点问题（slide 41）

A 和 B 互相听得到，B 和 C 互相听得到，但 A 和 C 听不到对方（距离太远或有障碍，或信号衰减）。A 和 C 都以为信道空闲，同时向 B 发送，在 B 处碰撞，而它们自己都不知道。

802.11 为什么不用碰撞检测（slide 42）

  • 发送时很难接收（检测碰撞）：自己的发送信号很强，收到的信号很弱（衰落）。
  • 即使能检测，也检测不到所有碰撞：隐藏终端、衰落。
  • 所以目标改为避免碰撞：CSMA/CA。802.11 a/b/g/n 都用 CSMA/CA，都有基站版和 ad hoc 版。

碰撞避免：RTS/CTS（slide 43–44）

  1. 发送方先用 CSMA 向 AP 发一个很短的请求发送 RTS。RTS 之间也可能碰撞，但它们很短，浪费少。
  2. AP 广播允许发送 CTS 作为回应。
  3. 所有节点都能听到 CTS（包括听不到发送方的隐藏节点），于是信道为这个发送方预留，其他站推迟发送。
  4. 发送方发送数据帧。

用很小的预约分组完全避免了数据帧的碰撞，解决了隐藏站碰撞。

2.2-8 生成树协议 STP

老师强调 · 课堂录音
  • STP 按步骤依次做：选根桥 → 各桥根端口 → 各网段指定端口 → 其余阻塞。

为了可靠，网络里常有冗余链路，形成物理环路。自学习交换机遇到环路会出问题（slide 54–55）：目的未知的帧被泛洪，沿环路转圈，被不断复制，形成广播风暴；交换机表也会被来回改写。STP 把一部分端口阻塞，让物理上可以有环，逻辑上是一棵树。

  1. 选根网桥：所有网桥中 ID 最小的当根。
  2. 选根端口：除根网桥外，每个网桥选到根网桥代价最小的端口作为根端口（R）。
  3. 选指定网桥/指定端口：每个 LAN 选一个到根网桥代价最小的网桥作为指定网桥，它连到这个 LAN 的端口是指定端口（D）。代价相同时选 ID 小的网桥。
  4. 所有根端口和指定端口进入转发状态，只有它们能转发帧；其余端口阻塞。
讲义例子（slide 53–61）：经过一个 LAN 网段代价为 1
  • B1 ID 最小 → 根网桥，它的两个端口都是指定端口。
  • B2、B3 经 LAN1 到根代价 1 → 端口 1 为根端口。B4 经 LAN2 代价 1 → 端口 1；B5 经 LAN3 代价 2 → 端口 1。
  • LAN2：B1 代价 0 → B1 是指定网桥，B2 端口 2 阻塞。LAN3：B3 和 B4 代价都是 1，B3 ID 小 → B3 端口 2 指定，B4 端口 2 阻塞。LAN4：B3 代价 1 < B5 的 2 → B3 端口 3 指定，B5 端口 2 阻塞。
往年题（2024/25 S2 Q2(b)，8 分）答案

四台交换机两两相连（S1–S2、S1–S3、S1–S4、S2–S3、S2–S4），PC 挂在各自端口上。Switch1 ID 最小是根，所有端口指定。Switch2、3、4 都直连 Switch1，根端口分别是 1、4、1。S2–S3 段和 S2–S4 段两端代价都是 1，Switch2 ID 小，Switch2 的端口指定，Switch3 端口 3、Switch4 端口 2 阻塞。完整表格见真题页。

2.2-9 VLAN 与路由器

老师强调 · 课堂录音
  • 一个广播域 = 一个子网 = 一个路由器接口；一个 VLAN = 一个广播域。

传统上一个站属于哪个 LAN 由它物理上接在哪里决定。如果要让两个不同物理 LAN 上的站在逻辑上同属一个网，就用 VLAN（虚拟局域网）：由软件配置而不是物理布线决定的局域网（slide 64）。

  • 成员依据：不同厂商用不同特征分组，如接口号、端口号、MAC 地址、IP 地址、IP 组播地址，或其中两种以上的组合。
  • 配置方式：手动、半自动、自动三种。
  • slide 65–67：一台交换机连三个 LAN → 用 VLAN 软件把同一台交换机的端口分组 → 两台交换机通过骨干用 VLAN 软件，让跨交换机的站属于同一个 VLAN。

路由器（slide 62）连接两个以上不同的网络，按目的网络地址（第 3 层）转发，在不同的广播域之间有选择地交换数据。每个接口在不同网络里，连接的逻辑子网不共享网络地址。

纯 ALOHA 的脆弱期为什么是 2F，而时隙 ALOHA 是 F？
纯 ALOHA 中帧可以在任意时刻开始，在本帧开始前 F 内开始的帧会和本帧的开头重叠，在本帧发送期间 F 内开始的帧会和本帧的结尾重叠，共 2F。时隙 ALOHA 只能在时隙边界发送，只有恰好同一个时隙开始的帧才会碰撞，所以是 F。
1 km 电缆，100 Mbps，帧 1000 字节，V = 2×10⁸。CSMA/CD 最大效率？
tprop = 5 µs，tframe = 80 µs，a = 0.0625，ρ = 1/(1 + 6.44 × 0.0625) = 1/1.4025 ≈ 0.713。
以太网第 3 次碰撞后，退避的 K 从哪个集合选？10 Mbps 时最长等多久？
K ∈ {0, 1, …, 2³ − 1} = {0..7}。最长 7 × 512 比特时间 = 7 × 51.2 µs = 358.4 µs。
交换机收到一帧，目的 MAC 在表里，且对应端口正好是帧进来的端口。怎么处理？
丢弃（过滤）。目的主机和源主机在同一个网段（比如都挂在同一个集线器上），它已经通过那个网段收到了这一帧，交换机不需要再转发。
STP 选指定网桥时两个网桥到根代价相同，怎么选？
选网桥 ID 较小的那个。讲义例子里 LAN3 上 B3 和 B4 代价都是 1，选 B3。
为什么 802.11 不能像以太网一样用碰撞检测？
发送时自己的信号远强于收到的信号，很难边发边听；而且即使能听，隐藏终端和衰落也会让发送方察觉不到接收方处的碰撞。所以改用碰撞避免（CSMA/CA + RTS/CTS）。

3.4 IP 分片

老师强调 · 课堂录音
  • 最常见错误：除最后一片外，每片数据长度必须是 8 的倍数（例如 MTU 576 时数据取 552，不是 556）。
  • 题里 DF 永远是 0。
  • 用表格作答（ID、MF、offset、total length）——“easy marks”。

MTU（最大传输单元）是一次网络层传输能承载的最大 PDU（数据报）大小（slide 24）。不同链路层要求的帧大小不同，例如以太网帧最大 1518 字节，所以 MTU 是 1500 字节。数据报经过 MTU 更小的网络时要分片：

  • 除最后一片外，每片的数据部分必须是 8 字节的整数倍（因为 offset 以 8 字节为单位）。
  • 分片可以在源主机或中间节点进行；分片还可以被再分片；重组只在目的主机进行。
  • Identification、Flags、Fragment offset 三个字段一起控制分片和重组：所有分片 ID 相同；除最后一片 MF = 1；offset = 本片第一个数据字节编号 ÷ 8。
每片最多能放的数据 = MTU − 首部长度，再向下取到 8 的倍数 每片 Total length = 本片数据 + 首部；offseti = 前面各片数据之和 ÷ 8

3.6 子网划分（定长 FLSM）

老师强调 · 课堂录音
  • 第一步先数子网数：把路由器拿掉，数剩下的“岛”（点到点链路也算）。这一步错了后面全错。
  • 全 0 / 全 1 子网：题目没说就自己选，写明假设。
  • 主机数 −2 永远要减。

分类编址的问题（slide 41）：一家拿到 B 类地址的公司要管 6 万多台主机；公司有多个部门，每个部门要自己的网络；出于安全也希望部门之间分开。解决办法：在网络号和主机号之间再加一层"子网"。

  • 从主机号借几位作子网号；子网掩码表示网络部分（含子网号）有多长，例如 255.255.255.0。
  • 子网掩码覆盖地址类别来决定每一位属于网络还是主机。
  • 子网结构对外部网络透明：外面只看到原来的网络号。

全 0 子网与全 1 子网（slide 45）

子网划分后的第一个子网（子网位全 0）叫 subnet zero，它的网络地址和原网络地址一样，容易混淆；最后一个子网（子网位全 1）叫 all-ones subnet，它的广播地址和原网络的广播地址一样。过去不鼓励使用这两个子网，所以工程师习惯用 2n − 2 计可用子网数。但实际上整个地址空间（包括这两个子网）一直都是可用的。考试题会明确说能不能用。

VLSM 中"不用全 0/全 1 子网"怎么理解

按 Week 6 官方解答的做法：一个子网的网络地址等于原网络地址（比如 200.100.50.0/27、/28、/30……）就算 subnet zero；广播地址等于原网络广播地址（以 .255 结尾）就算 all-ones subnet。这两种都不能用。其他位置都可以，包括 200.100.50.4/30 这种落在低地址区的小块（官方解答就把 /30 链路放在 .4）。

3.7 CIDR、VLSM 与路由汇总

老师强调 · 课堂录音
  • VLSM 技巧：子网按大小从大到小排序，然后一次性依次分配。

CIDR（无类域间路由）（slide 51）：子网部分可以是任意长度，地址写成 a.b.c.d/x，x 是子网部分（前缀）的位数。例如 200.23.16.0/23：前 23 位是子网部分，后 9 位是主机部分。

ISP 怎么分地址、怎么聚合（slide 58–60）

ISP 有地址块 200.23.16.0/20（11001000 00010111 00010000 00000000），把它分成 8 个 /23 给 8 个机构：200.23.16.0/23、200.23.18.0/23、……、200.23.30.0/23。ISP 对外只需宣告"把 200.23.16.0/20 开头的都发给我"，这就是路由聚合（层次编址让路由信息的宣告更高效）。如果机构 1 换到另一家 ISP（ISPs-R-Us），新 ISP 宣告 199.31.0.0/16 和 200.23.18.0/23；按最长前缀匹配，发往机构 1 的流量会走更具体的 /23 路由。ISP 的地址块由 ICANN 分配，ICANN 还管理 DNS、分配域名、解决纠纷。

VLSM：不同子网用不同长度的掩码

FLSM 让所有子网一样大，按最大的部门定块大小，小部门和 /30 链路会浪费很多地址。VLSM 让每个子网按需要选掩码。Topic 3 小结（Summary slide 11）把它列为"Subnetting and Supernetting (FLSM, VLSM & CIDR)"。

  1. 算每个子网要的块：需要 h 个地址 → 找最小的 m 使 2m − 2 ≥ h，前缀 = 32 − m。例：28 个 → /27（30）；14 个 → /28（14）；7 个 → /28（/29 只有 6）；2 个 → /30。
  2. 按块大小从大到小排序（Week 6 解答的建议）。
  3. 从小地址往大地址依次分配，每个块的起点必须是块大小的整数倍；按题目要求跳过全 0 / 全 1 子网。
  4. 写表：子网地址、掩码、可用范围（网络地址 +1 到广播地址 −1）、广播地址（下一个块起点 −1）。
  5. 检查有没有重叠、总数够不够，最后算汇总路由。

3.8 DHCP：动态主机配置协议

主机怎么拿到 IP 地址（slide 52）：系统管理员写死在配置文件里（Windows 控制面板、UNIX /etc/rc.config），或者用 DHCP 从服务器动态获取（"即插即用"）。DHCP 的目标（slide 53）：主机加入网络时动态获得 IP 地址；可以续租正在使用的地址；地址可以复用（只在连接时占用）；支持移动用户加入网络。

  1. DHCP discover（可选）：新主机广播"有 DHCP 服务器吗？"。src 0.0.0.0:68 → dst 255.255.255.255:67，yiaddr 0.0.0.0，transaction ID 654。
  2. DHCP offer（可选）：服务器回应"我是 DHCP 服务器，这个 IP 你可以用"。src 223.1.2.5:67 → dst 255.255.255.255:68，yiaddr 223.1.2.4，ID 654，lifetime 3600 s。
  3. DHCP request：主机请求这个地址"好，我要这个 IP"。src 0.0.0.0:68 → 255.255.255.255:67，yiaddr 223.1.2.4，ID 655。
  4. DHCP ACK：服务器确认"这个 IP 归你了"。src 223.1.2.5:67 → 255.255.255.255:68，yiaddr 223.1.2.4，ID 655，lifetime 3600 s。

四条消息都是广播（主机还没有地址）；服务器端口 67，客户端端口 68。DHCP 还能返回（slide 57）：第一跳路由器（默认网关）地址、DNS 服务器名字和地址、子网掩码。

课外补充：ARP（2023/24 S1 Q2(b) 考过"ARP 和 DHCP 比较"）

讲义只在 slide 16 提到"ARP is used in address mapping"。ARP 的作用是：已知同一子网内某台机器的 IP 地址，求它的 MAC 地址。主机广播 ARP 请求"谁是 223.1.2.9？请告诉 223.1.2.1"，目标主机单播回复自己的 MAC，请求方存进 ARP 缓存（有过期时间）。比较：DHCP 解决"我自己的 IP 是多少"（主机 → 服务器，客户/服务器模式，还给网关、DNS、掩码）；ARP 解决"对方 IP 对应哪个 MAC"（同一广播域内的主机之间，无需服务器）。两者都以广播开始。

3.9 NAT：网络地址转换

家庭网 10.0.0.0/24 里有 10.0.0.1、.2、.3 三台主机，NAT 路由器的 LAN 侧是 10.0.0.4，WAN 侧只有一个地址 138.76.29.7（slide 62）。所有离开本地网络的数据报源地址都是 138.76.29.7，只是源端口号不同；本网内部的数据报照常用 10.0.0.x 地址。

  1. 主机 10.0.0.1 发数据报 S: 10.0.0.1, 3345 → D: 128.119.40.186, 80。
  2. NAT 路由器把源改成 138.76.29.7, 5001，在 NAT 转换表里记下 (138.76.29.7, 5001) ↔ (10.0.0.1, 3345)。
  3. 回复到达：S: 128.119.40.186, 80 → D: 138.76.29.7, 5001。
  4. NAT 查表，把目的改回 10.0.0.1, 3345，交给内网主机。

3.10 IPv6（补充 slides）

老师强调 · 课堂录音
  • IPv6 是补充内容，不在期末考试范围。

讲义把 IPv6 放在 "Supplementary slides"，Summary slide 11 也标为 Supplementary。往年 Part I 没有考过 IPv6 计算，了解要点即可。

  • 动机：32 位地址空间快分配完了；新首部格式能加快处理和转发；首部的改变方便做 QoS。
  • 首部：固定 40 字节的基本首部，载荷最多 65 535 字节。基本首部后面可以跟最多 6 种扩展首部（逐跳选项、源路由、分片、认证、加密安全载荷、目的选项），很多原来是 IPv4 的选项。
  • 不允许路由器分片；去掉了首部校验和（减少每跳处理时间）；选项放在首部之外，由 "Next Header" 字段指示；ICMPv6 增加了 "Packet Too Big" 等消息和组播组管理功能。
  • 地址：128 位，地址空间 2128，是 IPv4 的 296 倍。人读写用冒号十六进制表示（8 组，每组 16 位）。全球单播地址分三段：站点前缀、子网号、接口号。
  • 过渡：不能所有路由器同时升级（没有"flag day"）。三种策略：双栈（同时运行 IPv4 和 IPv6）；隧道（IPv6 数据报整个作为载荷装进 IPv4 数据报，穿过 IPv4 路由器，如 B→E 段）；首部转换。过渡期一台主机可能同时有 IPv4 和 IPv6 地址。

网络层在哪里工作（slide 9）

  • 把传输层的报文段（segment）从发送主机送到接收主机。
  • 发送方：把报文段封装成数据报（datagram）；接收方：把数据报里的报文段交给传输层。
  • 每一台主机和中间的每一台路由器都运行网络层协议。slide 9 的图里，主机有完整的五层（应用、传输、网络、链路、物理），路由器只有下三层（网络、链路、物理）：路由器不看传输层和应用层。
  • 路由器检查 IP 数据报的首部字段，决定怎么转发它。

路由与转发的配合（slide 10）

每台路由器里都有一个路由算法，它算出一张本地转发表（"首部值 → 输出链路"）。分组到达时，路由器只做转发：取出首部里的值，和转发表比较，决定从哪条链路发出去。路由算法决定转发表里的值，转发只是查表。

小白版：最长前缀匹配到底在干什么，为什么要这样做
  1. 路由器在干什么？ 分组到了路由器，路由器只看分组首部里的目的地址，然后决定从哪个接口（出口）把它送出去。这一步叫转发，依据是路由器里的一张转发表：表的左边是"什么样的地址"，右边是"走哪个接口"。
  2. DA（目的地址）是从哪来的？ 一台主机要给另一台主机发数据时，会把数据装进一个 IP 数据报，在数据报的首部写上两个地址：源地址（自己的 IP）和目的地址 DA（对方的 IP，比如你打开一个网站，电脑先查到那台服务器的 IP 地址）。数据报在路上要经过很多台路由器，每一台都从首部读出 DA，查自己的转发表，决定下一步往哪送；DA 一路上不变。动画里的 DA-1～DA-4 是课件 slide 11–12 用来举例的 4 个地址，换成十进制是 200.23.22.161、200.23.24.170、200.23.28.5、200.23.64.1。
  3. "表项"是什么？是怎么来的？ 转发表的一行就是一个表项：左边是"一段目的地址"（前缀），右边是"从哪个接口送出去"（接口 = 路由器上连着一条链路的端口，0、1、2、3 就是 4 个端口的编号）。表项不是路由器自己瞎写的：路由选择算法 / 路由协议（本章后面的 Dijkstra、距离向量、OSPF、RIP、BGP，或者 SDN 的控制器）算出"去哪一片地址该走哪个端口"，再把结果填进转发表；管理员也可以手工写（静态路由）。左边为什么是一片一片的？因为地址是按块分配的：某个机构 / ISP 拿到一整块地址，下面的子网都在这块里面。拿课件这张表来说，可以想象这台路由器有 4 个端口：200.23.16～23 这一块网络在端口 0 那个方向；200.23.24～31 这一块在端口 2 那个方向，但其中 200.23.24 这个子网实际接在端口 1 那边（例如它换了接入的 ISP），所以单独写一行"例外"；除此之外的所有地址都往端口 3 送（比如通往上级 ISP，这就是 otherwise 默认路由）。
  4. 为什么不一个地址写一行？ IPv4 地址有 232 ≈ 43 亿个，一个地址一行，表大得放不下；而且路由器每秒要查几十万次，表越长查得越慢。老师原话："It is extremely important to keep the forwarding table as short as possible."
  5. 那怎么写？——用"前缀"表示一整段地址。 地址是成块分配的：同一个机构、同一片网络的地址，前面若干位都一样（就像同一个区的电话号码区号一样、同一片区的邮编前几位一样）。所以表里写"前 N 位是这些，后面随便"，就代表了一整段地址，写法是 前缀/长度。例如 200.23.16.0/21 = 前 21 位固定、后 11 位随便 = 211 = 2048 个地址，也就是 200.23.16.0 ～ 200.23.23.255。
  6. 怎么判断一个地址属不属于某一行？ 只比较前 N 位：完全一样就属于（匹配），有一位不同就不属于。动画里一位一位地比，比的就是这个；后面打 * 的位不用看。换成十进制更直观：看这个地址落不落在这一行管的范围里。
  7. 为什么会有好几行同时匹配？ 因为表里允许"大范围里挖一个小例外"。比如 200.23.24～31 这一大段都从接口 2 出去，但其中 200.23.24 这一小段要从接口 1 出去（它连在别的方向）。写法是：一行管大段（/21），再加一行管小段（/24）；而不是把剩下的 25、26、…、31 各写一行。另外最后还有一行 otherwise（前缀长度 0），它匹配所有地址，是兜底的默认路由。所以一个地址常常同时匹配好几行。
  8. 为什么选"最长"的那一行？ 前缀越长 = 规定死的位越多 = 管的范围越小 = 越具体。小例外本来就是为特殊情况写的，必须比大范围优先，不然例外永远不起作用。生活里的例子：信封上同时符合"新加坡"和"新加坡南洋理工大学 EEE 系"，当然按更具体的那个投递；公司规定"所有人周五可以在家办公，但值班的人除外"，值班的人要按"例外"那条执行。
  9. 这样做有什么好处？ ① 表很短（很多地址合成一行，叫地址聚合），查得快；② 网络有变化时，只需要加一行更具体的例外，不用改一大片；③ 默认路由保证任何地址都有路可走。
  10. 考试怎么写？ 计算题：把目的地址和每一行的前缀逐位比较，写出哪几行匹配、各是多少位，再写"by longest prefix matching, the most specific entry is chosen"，给出接口。问答题"为什么用前缀"：表短、查得快、地址按块分配可以聚合。

路由器的主要部件有四个：输入端口、输出端口、夹在它们中间的交换结构（switching fabric），以及连在交换结构上的路由处理器（routing processor）。

课外补充：四个部件的分工

输入端口、交换结构、输出端口负责搬运每一个分组，也就是转发，通常用硬件做，追求速度。路由处理器运行路由协议和路由算法，算出转发表，再把转发表下发给各个输入端口；它不搬运普通数据分组。

输入端口：三个处理阶段（slide 15）

  1. 线路端接（line termination）：物理层，按比特接收线路上的信号。
  2. 数据链路处理（data link processing）：链路层，例如以太网；执行链路层协议并拆封装，取出里面的 IP 数据报。
  3. 查表、转发、排队（lookup, forwarding, queueing）：这一步叫分散式交换（decentralized switching）：
    • 根据数据报的目的地址，用存在输入端口自己内存里的转发表查出该去哪个输出端口。每个输入端口自己查，不必每个分组都去问路由处理器，所以叫"分散式"。
    • 目标：以线速（line speed）完成输入端口处理，也就是分组进来多快，就要处理多快。
    • 排队：数据报到达得比送进交换结构的速度快时，就要在输入端口排队。

输出端口：方向相反（slide 20）

  1. 排队与缓存管理（queuing: buffer management）：交换结构送来数据报的速度比输出链路的发送速率快时，需要缓存。
  2. 数据链路处理：按输出链路的链路层协议重新封装成帧（slide 图里写的也是 protocol, decapsulation；对输出端口来说实际做的是封装）。
  3. 线路端接：物理层把比特发到线路上。

输出端口还要有调度策略（scheduling discipline）：队列里有好几个数据报时，决定先发哪一个。

课外补充：常见调度策略

最简单的是先来先服务（FIFO）；也可以按优先级（例如语音分组优先）、轮询，或者加权公平排队（WFQ，按权重分配带宽）。讲义只要求知道"需要调度策略"。

crossbar 的两句关键话（slide 19 的 Notes）
  • 严格无阻塞（strictly non-blocking）：只要目的输出端口空闲，分组就能通过；分组不会因为交换结构内部资源用完而被挡住。

课外补充：为什么"过两次总线"就慢一半

经内存交换时，一个分组要占用总线/内存两次（写入一次、读出一次）。如果内存每秒最多读写 B 个分组，转发速率最多只有 B/2 个分组每秒。经总线交换只占用一次，但所有端口共用这一条总线，总的交换速率不能超过总线速率。crossbar 让不同输入到不同输出的分组并行通过，总速率可以达到"端口数 × 线速"。

小白版：交换结构是什么，三种做法为什么快慢不同
  1. 路由器里面有什么？ 四大块（slide 14）：输入端口（把线路上的信号收进来、查转发表决定去哪个输出）、交换结构（把分组从输入端口搬到正确的输出端口）、输出端口（把分组发到下一条链路上）、路由处理器（跑路由协议、算出转发表）。可以把路由器想成一个火车站：输入端口是进站口，输出端口是各个站台，交换结构就是连接它们的通道。
  2. 为什么要关心交换结构的速度？ 每一个分组都要从这里过。如果它搬得比分组进来的速度慢，分组就只能在输入端口排队，排满了就丢。理想情况是交换结构的速度 ≥ 所有输入线路速度之和。
  3. 动画里的"时隙"是什么？ 把时间切成一小格一小格，每一格里一条总线只能搬一个分组。数时隙就是在比"搬完这 3 个分组要多久"。颜色和"→2"表示这个分组要去输出 2。
  4. ① 经内存：为什么最慢？ 最早的路由器就是一台普通电脑：分组先通过系统总线拷进内存，CPU 查表，再通过同一条总线拷到输出端口。一个分组要过两次总线，而且一次只能搬一个，所以 3 个分组要 6 个时隙。算速率时要除以 2。
  5. ② 经总线：好在哪、卡在哪？ 输入端口直接把分组放上一条共享总线送到输出端口，不经过内存和 CPU，只过一次总线；但所有端口共用这一条总线，同一时刻只能一个分组在上面，所以 3 个分组要 3 个时隙，总速度不能超过总线速度。
  6. ③ crossbar（纵横交换）：为什么快？ 它有很多条总线排成网格（n 个输入、n 个输出），像十字路口的立交桥：去不同输出的分组走不同的线，可以同时过，所以 1 个时隙就搬完。缺点：规模大、速度高时又复杂又贵。
  7. "两个去同一输出"为什么 crossbar 也要 2 个时隙？ 一个输出端口一次只能接收一个分组，两个分组抢同一个出口，只能一个先走——这叫输出争用，不是交换结构不够快。
  8. 考试怎么考？ 问答："比较三种交换结构，各自的瓶颈是什么"；计算："总线 X Gbps，经内存最多能转发多快"（记得除以 2）。

Q2. A router has 8 input ports, each at 1 Gbps. Its system bus can carry 10 Gbps. (a) If it switches via memory, can it forward at full line rate on all inputs? (b) If it switches via the shared bus? (c) Explain why a crossbar avoids this limit and state its drawback.

考点：经内存"过两次总线"、总线一次只能一个、crossbar 并行（计算 + 问答）。

怎么答
  1. 先算总需求：8 × 1 = 8 Gbps。
  2. 经内存：每个数据报写入一次、读出一次，总线要搬 2 次 → 能支持的最大转发速率 = 10 / 2 = 5 Gbps，与 8 比较。
  3. 经总线：只过一次 → 10 Gbps，与 8 比较。
  4. crossbar：写"2n 条总线、去不同输出可并行"，再写缺点。
看标准答案

Aggregate demand = 8 × 1 Gbps = 8 Gbps.

(a) Via memory, each datagram crosses the bus twice (input → memory, memory → output), so the maximum forwarding rate is 10/2 = 5 Gbps < 8 Gbps → No.

(b) Via a shared bus, each datagram crosses the bus once: 10 Gbps ≥ 8 Gbps → Yes (only one packet on the bus at a time).

(c) A crossbar uses 2n buses connecting n inputs to n outputs; packets to different outputs cross simultaneously, so it is not limited by a single bus. Drawback: large, high-speed crossbars are complex and expensive (and packets to the same output still contend).

易错：经内存不除以 2；以为 crossbar 下两个分组去同一输出也能同时过（那是输出争用）。

排队发生在哪里

输入端口和输出端口都可能排队，取决于速率是否匹配：

  • 输入排队：交换结构的速度比所有输入端口加起来慢，分组来不及送进交换结构。
  • 输出排队：交换结构送到某个输出端口的速度超过这条输出链路的发送速率，比如好几个输入同时往同一个输出送。
  • 两种情况都会带来排队时延，缓存满了就丢包。这正是 Part I Topic 1 讲的排队时延和丢包在路由器内部的来源。

队头（Head-of-the-Line, HOL）阻塞：排在队列最前面的数据报走不了，挡住了它后面本来可以走的数据报。slide 21 的图有两个时刻：

HOL 阻塞（按 slide 21 重画；队列右端是队首）
  1. 时刻 t：入1 队列有两个红色分组，入2 有一个蓝色分组，入3 有一个红色（队首）和一个绿色。红色都去 出1，蓝色去 出3，绿色去 出2。入1 和入3 的队首红色争同一个输出，这一时隙只能送一个（图中是入1 的红色）；蓝色正常送到 出3。

  • 后果：排队时延，以及输入缓存溢出造成的丢包。

消除 HOL：虚拟输出队列 VOQ（slide 23）

  • 做法：在每个输入端口为每个输出端口各开一个队列。输入 i 有 N 个队列 Q(i,1)…Q(i,N)，到达的分组 Ai,j(n) 按目的输出 j 放进 Q(i,j)。
  • 每个时隙由一个集中调度器算出一个匹配 M：每个输入最多送一个、每个输出最多收一个，再让 crossbar 按 M 接通。
  • 一个分组只会排在去同一个输出的分组后面，不会再被去别处的队首挡住，所以 HOL 阻塞被消除。
  • 代价（slide 23 的 Notes）：可能非常昂贵：N 个输入 × N 个输出共 N² 个队列，调度器每个时隙都要算匹配。
  • 延伸阅读（slide 27）：McKeown 等（INFOCOM 95）证明 VOQ 配合最大权重匹配可以达到 100% 吞吐量。

输出排队（slide 24）

slide 24 的图：时刻 t 三个输入的分组同时要去同一个输出；如果交换结构够快，它们都立刻通过，一个分组时间之后，这个输出端口的队列里排着 3 个分组（发走一个，后面还有两个），其他输出空着。

  • 需要交换结构有很高的带宽：例子里一个时隙要把三个分组送到同一个输出，交换结构和输出端口内存要比线速快 N 倍。
  • 经交换结构的到达速率超过输出线速时，在输出端口缓存。
  • 同样会有排队时延，以及输出缓存溢出造成的丢包。
  • 好处是没有 HOL 阻塞：分组一进来就到了自己的输出端口。
  • 折中：很多输入输出联合排队（CIOQ）设计在输入/输出端口线速、交换结构带宽和阻塞性能之间取平衡。

改进交换性能的调度：前瞻调度（slide 25–26）

slide 25 的第一句话：选择怎样的匹配，决定了在满足约束的前提下能达到多大吞吐量。约束是：每个输入每个时隙最多往交换结构送一个分组；每个输出每个时隙最多收一个分组。和"随机匹配"相比，前瞻调度（lookahead）多做了一步：

  1. 先在各输入队列的队首分组之间调度。
  2. 如果某个输入这一轮没送出、但队列里还有分组，就看它的第二个分组能不能调度（目的输出还空着）。
  3. 可以推广到看每个队列的前 w 个分组。

注意：每个输入仍然每时隙只送一个分组，只是不一定是队首。

小白版：为什么要排队，"队头阻塞"是怎么回事
  1. 为什么会排队？ 分组到达得太快、来不及送走时，多出来的先存在缓存里等着，这就是排队。可以在输入端口排（输入排队），也可以在输出端口排（输出排队）。
  2. 动画里每样东西是什么意思？ 左边三排是三个输入端口的队列，最右边是队首（最先进来、下一个要走的）；颜色 / "→2" 表示要去哪个输出；每一步是一个时隙；红框 = 队首被挡住；虚线框 = 本来可以走、却被挡在后面的分组。
  3. FIFO 输入排队有什么规矩？ 先进先出：每个输入端口每个时隙只能送队首那一个；每个输出端口每个时隙只能收一个。两个队首要去同一个输出，只能一个走（动画里编号小的先走），另一个等。
  4. 什么是队头阻塞（HOL blocking）？ 被挡住的队首后面，可能排着要去空闲输出的分组，可它们也走不了，只能干等——就像单车道上一辆要左转的车在等，后面要直行的车也全被堵住。结果是输出端口明明空着却没东西送，浪费了能力。端口很多时，FIFO 输入排队只能用到大约 58.6%。
  5. "吞吐量"是什么？ 平均每个时隙送出去的分组数 ÷ 端口数，也就是输出端口被用上的比例。2×2、目的均匀时，一半的时间两个队首撞车只送出 1 个，平均 1.5 个 / 2 个端口 = 0.75。
  6. 三种改进分别怎么做、代价是什么？ 前瞻：队首被挡时，看看第 2 个分组能不能走（调度更复杂）。VOQ：每个输入端口按"去哪个输出"分成几条队，像银行按业务分窗口排队，谁也挡不住谁，但要 N×N 条队列和复杂的调度，很贵。输出排队：交换结构做得比线路快 N 倍，所有分组先搬到输出端口那边排队，没有 HOL，吞吐可以到 100%，但交换结构和内存要非常快。老师说这是"性能和价格的折中"。

老师强调 · 课堂录音
  • Dijkstra 自己完整做一遍表格（含前驱节点 p(v)），“we may examine that”，第一次做很容易出小错。
  • 平局随便选一个；只需更新新着色节点的邻居。负权值超出范围。

假设：所有节点（或中央控制器）都知道网络拓扑和链路代价。目标：用全局信息算出从一个源到所有其他节点的最小代价路径。约束：链路代价必须为正（slide 39）。

初始：P = {1}，D1 = 0，对所有 j ≠ 1，Dj = dj1（不相邻为 ∞） Step 1：找 i ∉ P 使 Di = minj∉P Dj Step 2：P = P ∪ {i}；若 P 包含所有节点，停止 Step 3：对所有 j ∉ P，Dj = min[Dj, dji + Di]，回到 Step 1

进入 P 的节点叫被"着色"：着色意味着到它的最短路已经找到。算法一个一个地给节点着色，直到目的节点着色（只要一个目的）、所有节点着色，或者没有节点可以再着色（不连通图里不可达的节点永远不会着色）。有多条等长最短路时，算法保证找到其中一条（slide 41）。

不用 "Goto" 的伪代码（slide 43；2025/26 S2 Q3(a) 原题）

1  Initialization:
2    N' = {u}
3    for all nodes v
4      if v adjacent to u
5        then D(v) = c(u,v)

9    find w not in N' such that D(w) is a minimum

c(x,y) 是 x 到 y 的链路代价（不直接相邻为 ∞）；D(v) 是当前从源到 v 的路径代价；p(v) 是路径上 v 的前驱；N' 是已经找到最短路的节点集合。

为什么正确（slide 42，归纳法）

假设到 y 为止着色的节点都已经找到最短路，下一步选中边 e = yz（y ∈ P，z ∉ P）。设 Q 为"到 y 的最短路 + 边 yz"，Q' 为任意一条从 v 到 z 的路，zl 是 Q' 上第一个不在 P 中的点。因为算法每次选的是 P 外 D 最小的点、且代价全为正：w(Q) = d(v,y) + w(e) ≤ d(v, zl−1) + w(zl−1, zl) ≤ w(Q')。所以 Q 是到 z 的最短路。

N.5 距离向量与 Bellman-Ford Quiz 考

老师强调 · 课堂录音
  • 好消息传得快，坏消息传得慢（count-to-infinity，乒乓）；原因是只交换距离向量，不知道路径。
  • 毒性逆转：只对下一跳邻居谎报 ∞，对其他邻居说真话；3 个节点能解决，4 个节点仍可能失败——课上例子要会推。

"去 San Jose 怎么走？"路牌上写着 392 和 596（slide 46）。核心观察（slide 47）：如果 Di 是 i 到目的地的最短距离，而 j 是最短路上 i 的邻居，那么 Di = Cij + Dj。i 只有来自邻居的本地信息，就从各邻居里挑当前最短的（slide 48）。

Bellman-Ford 方程：Dx(y) ← minv { c(x,v) + Dv(y) }，对每个目的节点 y 每个节点定期把自己的距离向量 DV 发给所有邻居；收到邻居的新 DV 后用上式更新自己的 DV 只要所有节点持续交换 DV，估计值 Dx(y) 会收敛到真实最小代价 dx(y)（slide 50）

slide 49 的例子：节点 2 到节点 6 必须经过邻居 1、4、5 之一，它们到 6 的最短距离分别是 3、3、2。经 1：3 + 3 = 6；经 4：1 + 3 = 4；经 5：4 + 2 = 6。所以节点 2 选经 4，距离 4。

算法步骤（slide 51–52）

  1. 初始化：每个节点的路由表对每个目的 d 有一项；Dd(d) = 0；其他节点 Dj(d) = ∞，下一跳 nj = −1（未定义）。
  2. 发送：把新的距离向量发给直接相邻的邻居。
  3. 接收：在节点 j，对每个目的 d 找使距离最小的下一跳：Dj(d) = mini{Cji + Di(d)}（i 是 j 的邻居）。找到新的下一跳或新距离就替换 (nj, Dj)。
  4. 回到发送步骤，直到一轮迭代没有任何变化。

链路代价变化：好消息快、坏消息慢（slide 59–62）

  • 代价降低（x-y 从 4 变 1）：t0 y 发现变化，更新 DV 并通知邻居；t1 z 收到更新，算出新的到 x 的最小代价，发给邻居；t2 y 收到 z 的更新，自己的最小代价没变，不再发消息。"好消息传得快"。
  • 代价升高（x-y 从 4 变 60）：z 上次告诉 y 它到 x 是 5（其实是经过 y 的）。y 以为可以经 z 到 x，总距离 6（当然是错的）；z 又据此更新为经 y 的 7；……来回加，讲义说要 44 次迭代才稳定（直到经 y 的距离超过 z 直连 x 的 50）。这就是"坏消息传得慢"，也叫无穷计数（count-to-infinity）问题。
  • 毒性逆转 poisoned reverse：如果 z 经 y 到 x，z 就告诉 y "我到 x 的距离是 ∞"，这样 y 不会经 z 去 x。z 只对 y 撒这个谎，对其他邻居照实说，否则没人能经 z 到达 x。
  • 毒性逆转不能完全解决（slide 62）：在 y 和 z 之间再加一个节点 A，变化前最佳路径 Z-A-Y-X。Z 告诉 A 自己到 X 是 ∞，A 告诉 Y 自己到 X 是 ∞，但 Z 告诉 Y 自己到 X 是 6。链路变化后 Y 更新为 9，A 为 10，Z 为 11，Y 为 14……在信息正确更新之前存在环路 A-Z-Y。超过两个节点的环路毒性逆转检测不到。

小白版：距离向量怎么算，"毒性逆转"为什么会失败
  1. 路由器怎么知道去 x 有多远？ 距离向量算法里，每台路由器只知道自己到邻居的链路代价，不知道整张图。它问每个邻居："你到 x 有多远？" 然后算：到这个邻居的代价 + 邻居说的距离，取最小的那个，就是自己到 x 的距离，那个邻居就是下一跳。这就是 Bellman-Ford 方程 Dy(x) = minv{c(y,v) + Dv(x)}。像问路：你不认识路，就问隔壁的人"你去火车站要多久"，再加上走到他那里的时间。
  2. 动画里的数字是什么？ 线上的数字是链路代价（可以理解成这段路要走多久）；节点旁边的 "D(x) = 9，经 z" 表示它现在认为自己到 x 的最短距离是 9，下一跳是 z；彩色箭头指向下一跳。每一步只有一个节点更新，动画下面的说明写着它听到了什么、怎么算的。
  3. 出了什么事？ 链路 x–y 的代价突然从 4 变成 60（这条路变得很差）。y 想换一条路，可它只知道邻居报的数字，不知道邻居的路是不是经过自己。z 说"我到 x 只要 6"，y 就信了，改成经 z（9）——可 z 那条 6 其实是经过 y 的，已经是过时的消息了。
  4. 什么是无穷计数？ 大家都用别人过时的数字，互相以为对方能到 x，每轮只涨一点点，要更新很多很多次才慢慢涨到真实值。这就是"好消息传得快，坏消息传得慢"。在这期间，发往 x 的分组会在这几个路由器之间绕圈（环路）。
  5. 毒性逆转是什么？ 一个"说谎"的规则：如果我去 x 是经过你的，我就告诉你"我到不了 x"（∞），免得你又绕回来经过我。对其他邻居照样说真话。两个节点互相指的情况，它能解决。
  6. 为什么这里还会失败？ 这里的环有三个节点：y → z → A → y。每个节点只对自己的下一跳说谎：z 对 A 说 ∞、A 对 y 说 ∞，但 z 的下一跳不是 y，所以 z 对 y 说真话 6，y 照样上当。谎言没有传到需要它的人那里，于是照样无穷计数，每转一圈涨 5，直到 z 发现直连 x 的 50 更便宜才停下来。
  7. 考试怎么考？ 给一个小网络和一次代价变化，让你按 Bellman-Ford 方程逐次写出更新；问为什么会无穷计数；描述毒性逆转并说明它在三个以上节点的环里会失败。

怎么答
  1. (a) 关键词：只交换距离、不知道路径 → 用了对方过时的、其实经过自己的路。
  2. (b) "Z 经 Y 到 X → Z 告诉 Y 自己到 X 是 ∞，对其他邻居说真话"。

看标准答案

(a) Nodes exchange only distances, not paths. When a cost decreases, the better value spreads in one or two exchanges. When it increases, a node may switch to a neighbour's old route that actually goes through itself, so two nodes keep increasing their estimates step by step (count-to-infinity, 44 iterations in slide 60).

(b) If Z routes to X via Y, Z tells Y that its distance to X is ∞, so Y will not route to X via Z; Z tells all other neighbours the truth.

(c) Before: Dy = 4, DA = 5 (via y), Dz = 6 (via A). A tells y ∞ and z tells A ∞, but z tells y the truth, 6. After x–y = 60: y: min(60, 1+∞, 3+6) = 9 via z; A: min(1+9, 1+∞) = 10 via y; z: min(50, 1+10, 3+∞) = 11 via A; then y = 14, … The loop y → z → A → y has three nodes; each node only lies to its own next hop, so the false information still circulates and the values grow by 5 per round until z prefers its direct link (50). 讲义 slide 64 的四个思考题

  1. 删掉一条链路，要重算所有最短路吗？不用。从某个源看，只有最短路树用到这条链路的那些目的节点（这条链路下面的子树）受影响；树外的链路被删掉，源的最短路不变。
  2. 加一条链路呢？新链路 (i, j) 代价 c：若 D(i) + c ≥ D(j) 且 D(j) + c ≥ D(i)，最短路都不变；否则只需要从变短的那一端开始更新受影响的节点。
  3. 每条链路容量都不能低于某个下限怎么办？先把容量低于下限的链路全部删掉，在剩下的图上跑最短路算法。
  4. 路径不能经过某个节点怎么办？把这个节点和它的所有链路删掉（代价设为 ∞），再跑最短路。
往年考法：第二短路径（2023/24 S1 Q3(b)，5 分）

先用 Dijkstra 求出最短路 P = (e1, e2, …, ek)。第二短路径（不要求和 P 链路不相交）一定至少有一条链路不在 P 上，也就是说它一定不含 P 的某条边 ei。所以：对 i = 1…k，分别删掉 ei（代价设为 ∞），在剩下的图上跑一次 Dijkstra，得到路径 Pi；k 条 Pi 中最短的就是第二短路径。它可以和 P 一样长（存在两条等长最短路时）。这用的正是"删链路后重算"的思路。

N.6 层次路由与自治系统 Quiz 考

到目前为止的讨论是理想化的：所有路由器都一样，网络是"平"的（slide 66）。实际中：规模上有两亿个目的地，路由表放不下，交换路由表会淹没链路；管理自治上 Internet 是网络的网络，每个网络的管理者都想控制自己网络内的路由。

  • 把路由器聚合成区域：自治系统 AS（slide 67–68），由单一组织管理的一组路由器或网络，用 16 位 AS 号标识。同一 AS 内的路由器运行同一种 intra-AS（域内）路由协议，不同 AS 可以用不同的域内协议。AS 之间的路由叫 inter-AS（域间）路由。
  • 网关路由器：直接连到另一个 AS 的路由器。
  • 转发表由域内和域间路由算法共同配置（slide 69）：域内算法设置内部目的地的表项，域间和域内一起设置外部目的地的表项。

域间路由的任务（slide 70–73）

AS1 的某台路由器收到目的在 AS1 外的数据报，应该转给哪台网关路由器？AS1 需要：① 学习哪些目的地经 AS2 可达、哪些经 AS3 可达；② 把这些可达性信息传播给 AS1 内所有路由器。这是域间路由的工作。

  • 设置 1d 的转发表：AS1 通过域间协议得知子网 X 经 AS3（网关 1c）可达。域间协议把可达性传给所有内部路由器；路由器 1d 根据域内路由信息知道自己的接口 i 在去 1c 的最小代价路径上，于是在转发表里加 (X, i)。
  • X 经 AS2 和 AS3 都可达：1d 要决定往哪个网关送，这也是域间协议的工作。一种做法是热土豆路由 hot potato：从域间协议得知 X 经多个网关可达 → 用域内路由信息算到每个网关的最小代价 → 选代价最小的网关 → 从转发表找到通往该网关的接口 I，写入 (X, I)。也就是"尽快把分组送出自己的 AS"。

N.7 路由协议：RIP、OSPF、BGP Quiz 考

老师强调 · 课堂录音
  • RIP 距离 = 经过的子网数（含目的子网）；RIP 跑在应用层、用 UDP。
  • BGP：首要目标是执行策略而非最优性能；通告路径 = 作出承诺；NEXT-HOP 属性在多条 AS 间链路时指定用哪条。

域内路由也叫内部网关协议 IGP（RIP、OSPF 等）；域间路由也叫外部网关协议 EGP，现在用的是 BGP。边界网关路由器同时运行 IGP 和 EGP（slide 75）。

RIP：路由信息协议（slide 77–79）

  • AS 内部使用的域内协议，用距离向量算法。路由表由应用层进程 routed 管理，跑在 UDP 上，端口 520。
  • 度量：跳数（经过的子网数，包括目的子网）。最大跳数 15，适合小网络；16 表示无穷大；上限小也限制了无穷计数问题。
  • 每 30 秒向邻居发一次更新；最坏情况下应该在 180 秒内收到每个邻居的更新，否则认为到该邻居的链路断了，代价设为 16（无穷）。检测到变化立即通知邻居，加快收敛。

OSPF：开放最短路径优先（slide 80–87）

  • 修补 RIP 的缺陷。每台路由器学习完整拓扑：监视到每个邻居的链路状态并泛洪给其他路由器，每台都建一个相同的链路状态数据库，以自己为根算最短路树。网络有故障时通常比 RIP 收敛快。
  • 链路 = 路由器上的一个接口；链路状态 = 接口及其与相邻路由器的关系：接口的 IP 地址/掩码、所连网络类型、链路的度量（代价）。所有链路状态构成链路状态数据库。
  • 特性：允许到同一目的地的多条路由（如每种服务类型一条）；路由消息里带子网掩码，支持 VLSM/CIDR；链路代价灵活，1 到 216；可以把流量分到多条等代价路径上；有认证，只和可信邻居交换信息；用区域 area 把 AS 分成几块。
  • 泛洪：把收到的分组从除进入端口外的所有端口转发出去；只要源和目的之间有路径，分组最终会到达；但会产生指数级的传输次数。受限泛洪：用 TTL 限制跳数（每个节点减 1）；每个节点泛洪前加上自己的 ID 防止重复；源在每个数据报里放序号，节点记录（源地址, 序号），丢弃重复。
  • 链路状态路由的原理（slide 85）：每台路由器和邻居建立"邻接"关系；生成链路状态通告 LSA = (link id, 链路状态, 代价, 链路的邻居)，分发给所有路由器；每台路由器维护所有收到的 LSA（拓扑数据库），把网络描述成带权图；用它跑最短路算法得出到每个节点的路由。
层次 OSPF（slide 86–87；2025/26 S1 Q3(a) 原题）
  • 两级层次：本地区域（area）和主干（backbone）。
  • 链路状态通告只在区域内泛洪；每个非边界路由器只有自己区域的详细拓扑，跨区域的流量交给区域边界路由器。
  • 区域边界路由器：把到本区域内各网络的距离"汇总"，通告给其他区域边界路由器。
  • 主干路由器：在主干内运行 OSPF。
  • 边界路由器（boundary router）：连到其他 AS。
  • 好处：LSA 泛洪范围小、每台路由器的数据库和计算量小，能扩展到大型网络；一个区域的变化不会让整个 AS 重新计算。

BGP：边界网关协议（slide 88–97）

  • AS 之间的域间路由协议，"把 Internet 粘在一起"；用 TCP 发送路由消息（BGP 对等体之间是半永久 TCP 连接）。
  • BGP 既不是链路状态也不是距离向量，而是路径向量协议：通告到目的地的 AS 号序列。可扩展到全球 Internet，应该促进地址聚合，完全分布式。路径选择由策略主导，而不是路径最优。BGP 的目的地不是主机，而是 CIDR 前缀。
  • eBGP：从相邻 AS 获取子网可达性；iBGP：把可达性传播给 AS 内部所有路由器；根据可达性和 AS 策略确定到其他网络的"好"路由；向 Internet 通告自己的存在："I am here"。
  • AS3 向 AS1 通告一个前缀，就是承诺会把去往该前缀的数据报转发过去；AS3 可以在通告里聚合前缀。例：3a 和 1c 之间的 eBGP 会话把 AS3 的前缀可达性告诉 AS1；1c 用 iBGP 发给 AS1 内所有路由器；1b 再通过 1b-2a 的 eBGP 会话通告给 AS2。路由器学到新前缀后在转发表里建一项。
  • 属性：前缀 + 属性 = "路由"。AS-PATH：通告经过的 AS 序列（例如 AS2 → AS1 → 再转给 AS3 时为 AS2, AS1）。NEXT-HOP：通往下一跳 AS 的具体内部路由器，例如 AS3 发给 AS1 的通告，NEXT-HOP 是 3a 通往 1c 的那个接口的 IP 地址。网关路由器收到通告后用导入策略决定接受还是拒绝（如"永远不经过 AS x"）。
  • 路由选择（有多条路由时依次比较）：① 本地偏好值（策略决定）；② 最短 AS-PATH；③ 最近的 NEXT-HOP 路由器（热土豆）；④ 其他准则。
  • 路由策略（slide 95–96）：A、B、C 是提供商网络，X、W、Y 是末梢（stub）网络。X 双归属（连到 B 和 C），不想让 B 经 X 到 C 的流量过自己，所以 X 不向 B 通告到 C 的路由。A 向 B 通告 AW，B 向 X 通告 BAW；B 不应该向 C 通告 BAW：W 和 C 都不是 B 的客户，B 帮 CBAW 转发拿不到收入，B 只想为自己的客户转发，逼 C 经 A 去 W。
为什么域内、域间用不同的协议（slide 97）
策略域间：管理者要控制自己的流量怎么走、谁能经过自己的网络。域内：单一管理者，多数情况下不需要策略决策
规模层次路由减小路由表、降低更新流量
性能域内可以专注于性能；域间的策略常常压倒性能考虑
小白版：自治系统、BGP 通告和"热土豆"是什么
  1. 互联网是怎么分块管理的？ 互联网太大，被分成很多自治系统 AS：每个 ISP、每个大机构自己管一个 AS。AS 内部用 OSPF、RIP 这类域内协议算路；AS 之间用 BGP。动画里有三个 AS（三个灰色大框），子网 X 是一个目的网络，它同时连着 AS2 和 AS3。
  2. "网关路由器"（出口）是什么？ AS 边上、直接连着别的 AS 的路由器。AS1 有两个：1b 连 AS2，1c 连 AS3。1a、1d 在里面，不直接连外面，想把分组送出 AS1，必须先送到 1b 或 1c。
  3. "通告"是什么？ 一个 AS 告诉邻居 AS："我能到 X，你可以把去 X 的分组交给我。"通告里带着两个关键信息：AS-PATH（这条路会经过哪些 AS）和 NEXT-HOP（从哪台路由器进来）。老师说：通告就是作出承诺，答应替别人转发。
  4. eBGP 和 iBGP 有什么区别？ AS 之间的边界路由器互相说 = eBGP（动画里的实线箭头）；边界路由器把听到的消息转告给本 AS 内部的所有路由器 = iBGP（虚线箭头）。
  5. 1d 为什么要"选"？ 1d 听到了两条去 X 的路：从出口 1c 出去走 AS3，或从出口 1b 出去走 AS2。可是转发表里一个目的地只能写一个出口接口，所以必须挑一个。
  6. 按什么顺序选？ ① 本地偏好（公司政策，比如和哪家签的合同便宜）→ ② AS-PATH 短（经过的 AS 少）→ ③ 最近的 NEXT-HOP（热土豆）→ ④ 其他。前一条分出胜负就不看后面的。热土豆只是第 ③ 条：只有前两条都打平时才用到。
热土豆一步一步讲（对着动画看）
  1. 先打个比方。 你是新加坡一家快递公司（AS1），收到一个寄往国外 X 的包裹。有两家合作的国外快递都能送到 X：A 公司在你的东仓库（1b）收件，B 公司在你的西仓库（1c）收件。包裹现在在你的 1d 网点。你自己的货车每跑一公里都是你出钱；一旦交给合作公司，后面的运费就是人家的事。最省你自己钱的做法：送到离 1d 最近的那个仓库交出去，不管人家之后要跑多远。这就是热土豆：土豆烫手，赶紧扔出去。
  2. 第 1 步：知道有哪些出口（slide 72 第 ① 格）。 靠 BGP：eBGP 让 1b、1c 从邻居 AS 听到"能到 X"，iBGP 再让 1d 也知道。所以 1d 的候选是"出口 1b"和"出口 1c"。
  3. 第 2 步：算到每个出口的代价（第 ② 格）。 用的是 AS1 内部的路由信息，也就是 OSPF 用 Dijkstra 算出的最短路，和前面学的 Dijkstra 完全一样，只是终点换成了出口路由器。动画里：1d→1b 直连 = 2；1d→1c 直连 = 4，绕 1d→1b→1a→1c = 2+1+2 = 5，所以取 4。
  4. 第 3 步：选代价最小的出口（第 ③ 格）。 2 < 4 → 选 1b。只比 AS1 内部这一段；AS2、AS3 内部还要走几跳，AS1 看不见（老师强调：我们不知道别的 AS 的内部结构），也不关心。
  5. 第 4 步：写进转发表（第 ④ 格）。 1d 本来就知道"去 1b 从哪个接口出去"（内部路由算好的），记这个接口为 I，然后加一条表项 (X, I)。以后去 X 的分组一来，查表就从 I 发出去。
  6. 为什么说它"自私"？ 分组越早离开 AS1，占用 AS1 的链路和带宽就越少。至于整条路（包括别人的 AS）是不是最短，热土豆不管。老师原话："This is a quite selfish approach"，但整个互联网的协议本来就是按"大家都自私"来设计的。
  7. 同一个 AS 里大家都选同一个出口吗？ 不一定。每台路由器各自算、各自选：在动画里切到"每台路由器各选各的"，1a、1b、1d 选 1b（AS2），1c 选它自己（AS3）。老师上课就是这么讲的：离 1c 近的送 1c，离 1b 近的送 1b。
  8. 内部代价一变，出口会变吗？ 会。切到"内部代价变了"：1b–1d 从 2 变成 9 以后，1d 到 1b 最少要 7（1d→1c→1a→1b），到 1c 只要 4，于是改走 1c。目的地没变，只是自己内部的代价变了，出口就换了。
  9. 切到"本地偏好更高"会怎样？ 规则 ① 先比，政策直接决定选经 AS3（1c），哪怕 1b 更近也不走，热土豆根本轮不到。这说明 BGP 策略优先于性能，也是为什么域内和域间要用不同的路由协议（Policy / Scale / Performance，slide 97）。
  10. 考试怎么写？ 一句话定义："Hot potato routing: among routes with the same local preference and the same AS-PATH length, a router chooses the gateway (NEXT-HOP) with the least intra-AS cost, so that the packet leaves its own AS as quickly as possible, ignoring the cost outside the AS." 再加上四步：learn gateways via BGP → intra-AS costs to each gateway → choose the least-cost gateway → find interface I, enter (X, I) in the forwarding table。
  11. 会怎么考？ 给几条路由（本地偏好、AS-PATH、到 NEXT-HOP 的代价），让你按顺序选出一条并说明理由（右边 Q7）；或者给一张 AS 内部的图，问某台路由器按热土豆选哪个出口；或者解释热土豆和 BGP 策略（提供商不帮非客户转发）。

每台路由器本地的功能：决定从输入端口进来的数据报转发到哪个输出端口（转发功能） 全网的逻辑：决定数据报在源到目的的端到端路径上怎么在路由器之间路由。两种做法：传统路由算法在每台路由器里实现（每路由器控制平面，各路由器的路由算法组件相互交互）；SDN 在（远程）服务器里实现（逻辑集中的控制平面，一个独立的远程控制器和各路由器里的本地控制代理 CA 交互）

为什么要逻辑集中的控制平面（slide 103–105）

  • 网络管理更容易：避免路由器配置错误，流量走向更灵活。
  • 基于表的转发允许"编程"路由器：集中编程更容易（集中算表再下发）；分布式编程更难（每台路由器都运行分布式算法得到表）。
  • 控制平面的开放（非专有）实现。
  • 传统方法做流量工程很难：在 u-v-w-x-y-z 的例子里，如果 w 想让蓝色和红色流量走不同的路，用基于目的地址的转发 + LS/DV 路由做不到；网络运营者想把 u 到 z 的流量分在 uvwz 和 uxyz 两条路上做负载均衡，也做不到（或者需要新的路由算法）。

通用转发与 OpenFlow（slide 110–117）

  • 每台路由器有一张流表，由逻辑集中的路由控制器计算和下发。
  • 流由首部字段定义。通用转发是简单的分组处理规则：模式（匹配首部字段的值）、动作（对匹配的分组：丢弃、转发、修改，或者送给控制器）、优先级（消除重叠模式的歧义）、计数器（字节数和分组数）。

小白版：SDN、流表和"按优先级匹配"是什么
  1. 传统路由器和 SDN 有什么不同？ 传统路由器每台自己跑路由算法、自己算转发表（每台里都有"控制平面"），转发时只看目的地址。SDN 把"算"的部分搬到一个集中的控制器上，交换机只管按控制器下发的流表办事。
  2. 流表的一行（表项）是什么？ 匹配条件（看分组首部的哪些字段：从哪个端口进来、源/目的 MAC、源/目的 IP、协议、端口号）+ 动作（从某端口转发、丢弃、改写、交给控制器）+ 优先级 + 计数器（命中了多少分组和字节）。表里写 * 表示"这个字段不管"。
  3. 分组首部里的这些字段是哪来的？ 发送方在发包时就写好了：IP 首部里有源 / 目的 IP 地址和协议类型，TCP/UDP 首部里有端口号（端口号表示是哪种应用，例如 22 是远程登录 SSH、80 是网页）。交换机看的就是这些。
  4. 怎么匹配？ 按优先级从高到低一条一条比，找到第一条所有写出来的字段都一样的，就执行它的动作，后面的不再看。
  5. 为什么要优先级？ 规则会重叠。比如分组 2 去 51.6.0.8，又是 TCP 22：它同时符合"去 51.6.0.8 → 端口 6"和"TCP 22 → 丢弃"。优先级决定听谁的：防火墙那条更高，所以被丢弃。
  6. 都不匹配怎么办？ 最后一条全是 * 的 table-miss，把分组交给控制器，控制器决定怎么处理，还可以下发一条新规则。
  7. 这样有什么好处？ 能按源地址、端口、协议区分流量，做到传统"只看目的地址"的转发做不到的事：防火墙、按来源分流、负载均衡、NAT，都用同一套 match + action。代价是控制器很关键，它坏了影响全网（老师说的 single point of failure）。
  8. 考试怎么考？ 给一个策略让你写流表（每行写匹配、动作、优先级，最后加 table-miss）；解释为什么按目的转发 + LS/DV 做不到；说出 SDN 的挑战。

T.1 传输层做什么 期末考

老师强调 · 课堂录音
  • 传输层只在两端主机工作，路由器上没有传输层。寄包裹的比喻：直接丢进邮局（UDP）vs 先打电话约好、对方收到再回电（TCP）。
  • UDP 简单、快、不可靠。今天 Internet 上 UDP 承载的流量已经超过 50%（多媒体），可 UDP 既没有拥塞控制也没有流量控制，这是个还没有好办法的问题。
  • 流量控制 = 别让发送方淹没接收方；拥塞控制 = 别让发送方把网络塞爆。名字像，意思完全不同。
  • 进程到进程的逻辑通信（slide 4）：网络层把数据报从一台主机送到另一台主机；传输层再把它交给主机里的某个进程（应用程序）。"逻辑"的意思是：在应用看来两端好像直接连着，实际中间隔着很多路由器。
  • 只在端系统里运行：路由器只到网络层，没有传输层。发送方把应用报文切成报文段（segment）、加上传输层首部交给网络层；接收方把报文段重新拼成报文交给应用。
  • Internet 上有两个传输协议可选：TCP 和 UDP。

T.2 端口号与套接字 期末考

每一层都有自己的地址（slide 8）：链路层是 MAC 地址，网络层是 IP 地址，传输层是端口号。IP 地址找到主机，端口号找到主机里的进程。

端口号 = 16 位整数：0 ～ 216 − 1 = 65535 知名端口 well-known：0 – 1023（保留给特定服务） 注册端口 registered：1024 – 49151 动态端口 dynamic：49152 – 65535

套接字 socket（slide 10–11）

  • 套接字是进程间通信在传输层的端点，应用层和传输层之间的"门"。老师的比喻是墙上的电源插座：你插上就有电，不用知道后面整个电力系统怎么工作。

T.4 UDP：首部与校验和 期末考

老师强调 · 课堂录音
  • UDP 校验和就是 Part I 的 Internet checksum（16 位相加、进位回卷、取反），老师说不再重复；补零之类是"small details"。

T.5 可靠数据传输的目标与 FSM 记号 期末考

老师强调 · 课堂录音
  • RDT 的目标：不出错、不丢、不重复、按序。"无差错"指检错算法查得出的错都处理了。
  • RDT ≠ TCP：TCP 实现了 RDT，还多了拥塞控制等；RDT 的思想其他层也用。
  • FSM 里"什么都不做"写 Λ。

可靠数据传输 RDT（slide 29）：给上层提供一条"可靠信道"的假象——传过去的比特不出错、不丢失，并且按发送顺序交付；老师补充：同样重要的是不重复。这个模型在应用层、传输层、链路层都适用；TCP 实现了 RDT，但 RDT 不等于 TCP（TCP 还有拥塞控制等）。下层信道越"坏"，RDT 协议就越复杂（slide 30–32）。

"无差错"是什么意思

总会有极少数差错图样能骗过检错算法。RDT 说的"无差错"是指：检错算法能查出来的错都能被发现并纠正（重传）。漏检的那一点点不算协议的错（课堂）。

四个接口函数（slide 33）

函数在哪一边谁调用、做什么
rdt_send(data)发送方上层（应用）调用，把数据交给 RDT："请可靠地送过去"
udt_send(pkt)发送方 / 接收方RDT 调用，把分组交给下面不可靠的信道发出去（u = unreliable）
rdt_rcv(pkt)接收方 / 发送方分组从信道到达时被调用（接收方收数据、发送方收 ACK 都用它）
deliver_data(data)接收方RDT 调用，把数据交给上层

只考虑单向数据传输（发送方 → 接收方），但 ACK/NAK 这些控制信息是双向流动的（slide 34）。

FSM 怎么读（slide 34–35）

一条状态转移 = 一句话
  • 圆圈 = 状态；箭头 = 状态转移；横线上面写引起转移的事件，横线下面写转移时执行的动作；Λ 表示没有事件或没有动作；虚线箭头指向初始状态。
  • 当前状态 + 下一个事件 → 唯一确定下一个状态。
  • 读法："在【状态】时，如果【事件】，就做【动作】，然后进入【下一状态】。"自环（箭头回到自己）就是"做完动作，还在原状态"。
  • 为什么用 FSM：开始画会觉得麻烦，习惯后会喜欢它——每个状态下可能发生什么事件、该怎么反应，一目了然，漏了哪种情况一眼就能查出来（课堂）。

rdt2.0 的致命缺陷（slide 44）

如果 ACK/NAK 本身出错了怎么办？发送方收到一个看不懂的回应，不知道接收方那边发生了什么。直接重发行不行？如果其实是 ACK（接收方已经收到并交付了），重发的分组会被接收方当成新数据再交付一次——上层收到重复数据，违反 RDT。而且传输层不能去读数据内容来判断"这个我是不是收过"（传输层不应该碰应用数据）。

解决办法：发送方看不懂 ACK/NAK 时就重发当前分组；给每个分组加序号；接收方看到序号和上一个一样，就知道是重复，丢弃不交付。在实验 17 里选"rdt2.0 · ACK 出错"可以亲眼看到重复交付。

rdt2.1：加序号 0/1（slide 45–47）

为什么"收到出错的 ACK 或 ACK1"时什么都不做？（老师专门解释）

和 2.2 不同，3.0 收到出错或序号不对的 ACK 时不立刻重传，只等超时。原因是过早超时（slide 53–54 的 (d)）：ACK1 因为拥塞迟到了，发送方先超时、重发了 pkt1；接着迟到的 ACK1 到了，发送方发 pkt0；接收方收到重发的 pkt1，认出是重复，又回一个 ACK1。现在发送方在等 ACK0，却收到这个 ACK1：

  • 如果立刻重发 pkt0：接收方会收到两份 pkt0，又回两个 ACK0，发送方之后在等 ACK1 时又收到多余的 ACK0、又重发……从此每个分组都被发两遍，一直错位下去。
  • 什么都不做：等 pkt0 的 ACK0 正常回来就好了。多余的 ACK 被安静地吃掉，节奏马上恢复。slide 54 在这一步写的就是 "do nothing"。

老师强调 · 课堂录音
  • 传播时延由距离决定，缩短不了；发送速率越来越高，L/R 相对 RTT 越来越小 → 停等利用率极低（例子 0.027%），必须用流水线。

rdt3.0 是对的，但性能很差（slide 55："performance stinks"）。发送方发完一个分组（用时 L/R），要再等一个往返 RTT 才收到 ACK，这段时间链路空着。

发送一个分组的时间：Dtrans = L / R（L 分组长度 bit，R 链路速率 bit/s） 停等：每 RTT + L/R 才发一个 → Usender = (L/R) / (RTT + L/R)（发送方忙着发送的时间比例） 流水线一次发 N 个：U = N·(L/R) / (RTT + L/R)，N·(L/R) ≥ RTT + L/R 时 U = 1 要让 U = 1 至少需要 N ≥ (RTT + L/R) / (L/R) = 1 + RTT·R/L（向上取整） 吞吐量 = U × R；ACK 很短，传输时间按 0（图里 ACK 画成一条线而不是一条带）
slide 55 的例子（逐步）
R = 1 Gbps，传播时延 15 ms → RTT = 30 ms，L = 8000 bit（1 KB） L/R = 8000 / 109 = 8 µs = 0.008 ms U = 0.008 / (30 + 0.008) = 0.008 / 30.008 = 0.00027 = 0.027% 吞吐量：每 30.008 ms 才送出 1 KB ≈ 33 kB/s（≈ 267 kbps），而链路有 1 Gbps 要满载：N ≥ 30.008 / 0.008 = 3751 个分组同时在路上

"网络协议限制了物理资源的使用"。slide 58：一次发 3 个，利用率变成 3 倍：3 × 0.008 / 30.008 ≈ 0.0008（slide 写成 .0024 和 0.00081，分子应为 0.024，要点是"变 3 倍"）。

再练一个
R = 10 Mbps，L = 1500 字节 = 12 000 bit，RTT = 20 ms L/R = 12 000 / 107 = 1.2 ms 停等：U = 1.2 / (20 + 1.2) = 1.2 / 21.2 = 0.0566（5.66%）→ 吞吐量 0.566 Mbps N = 5：U = 5 × 0.0566 = 0.283 → 2.83 Mbps 满载需要 N ≥ 21.2 / 1.2 = 17.67 → N = 18
和 Part I 链路层的公式是同一个

T.8 流水线协议之一：Go-Back-N 期末考

老师强调 · 课堂录音
  • GBN：累积 ACK，只有一个定时器，跟着最老的未确认分组。收到 ACK 后给新的最老分组重新计时，好像它刚发出——"a little bit rough"，但简单，高速时简单很值钱。
  • 超时就把所有已发未确认的分组全部重发，哪怕有些对方其实已经收到了。窗口大小以后会受流量控制约束。

流水线（slide 57）：允许发送方有多个"已发出、还没确认"的分组在路上。代价：序号范围要变大（0/1 不够了），发送方和/或接收方要有缓存。两种基本做法：Go-Back-N 和选择重传，和 Part I 链路层学过的 ARQ 是同一回事。

两种流水线协议一览（slide 59）
Go-Back-N（GBN）选择重传（SR）
在路上的未确认分组最多 N 个最多 N 个
接收方怎么确认累积 ACK；中间有缺口时，缺口之后的不确认对每个分组单独 ACK
定时器一个，给最老的未确认分组每个未确认分组一个
超时后重发所有未确认分组只重发那一个

发送方（slide 60–62）

  • 首部里有 k 位序号；"窗口" = 最多 N 个连续的、未确认的分组。变量 base = 最老的未确认分组的序号，nextseqnum = 下一个要用的序号。
  • ACK(n) 确认序号 ≤ n 的所有分组（累积 ACK），可能收到重复 ACK。
  • 定时器只给最老的在途分组；timeout(n)：重发 n 以及窗口里所有序号更大的分组。

初值 base = 1，nextseqnum = 1（slide 61）。注意收到 ACK 后"重新计时"：新的最老分组其实早就发出去了，却被当成"刚发"开始计时——老师说这里 GBN 有点"粗糙"（rough），但简单，高速时简单很值钱。slide 65 的例子里，序号小于 base 的重复 ACK 直接忽略。

接收方（slide 63–64）：只有一个状态

  • 只记一个变量 expectedseqnum（初值 1）。收到没出错、序号正好是 expectedseqnum 的分组：交付，回 ACK(expectedseqnum)，expectedseqnum++。
  • 其他所有情况（default：出错、乱序）：丢弃，不缓存，重发上一个 ACK（最高的按序收到的序号）。所以会产生重复 ACK。
  • 为什么用累积 ACK 很自然：GBN 下如果 k 已经交付，比 k 小的一定都交付了。

T.9 流水线协议之二：选择重传 Selective Repeat 期末考

老师强调 · 课堂录音
  • SR：逐个 ACK、每个分组一个定时器、接收方缓存乱序分组。重传少，但两端都复杂；一个 RTT 里能发的分组越多，负担越重。
  • slide 67 的图有错（出版社的图）：接收方窗口第 5 格是粉色，但发送方那一格还没发送，应该是蓝色。
  • GBN 接收方可以对中间收到的分组也回 ACK；SR 接收方必须对每个收到的分组回 ACK。
  • 接收方对每个正确收到的分组单独 ACK；乱序到达的先缓存，等缺口补上再按序交付（slide 66）。
  • 发送方只重发没收到 ACK 的分组；每个未确认分组有自己的定时器。
  • 发送方窗口：N 个连续序号，限制已发未确认分组的序号范围。接收方也有一个大小为 N 的窗口。

UDP 报文段带 100 字节数据，首部"长度"字段填多少？
长度包括 8 字节首部：100 + 8 = 108（字节）。
为什么 rdt2.1 只需要 0 和 1 两个序号？
停等协议同一时间只有一个分组在途，接收方只需要分清"这是我期待的新分组"还是"上一个分组的重传"。两个序号交替使用就足够区分。
rdt2.2 的接收方在等序号 0 时收到一个出错的分组，它回什么？发送方收到后做什么？
回 ACK1（"我最后正确收到的是 1"）。发送方在等 ACK0，收到 ACK1 = 重复 ACK，等同于 NAK → 重传 pkt0。
rdt3.0 发送方在"等 ACK0"时收到 ACK1，为什么不立刻重传？
ACK1 可能是过早超时造成的多余 ACK。立刻重传会让之后每个分组都被发两遍；什么都不做（Λ），等 pkt0 的 ACK0 或超时即可。
